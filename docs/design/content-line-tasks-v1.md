## 0. 怎么实现（协作规则落地）

| 规则 | 在本项目怎么做 |
|---|---|
| 小步改动 | 每个任务 = 一次可回滚变更（1 个 PR 级）；不顺手重构无关文件 |
| 测试先行 | **先写红测试** → 再实现 → 绿；禁止改旧断言「凑绿」 |
| 完成有证据 | 任务完成条件 = 命令输出 + 覆盖率 + 必要截图/走查记录 |
| 迁移/删文件/重构模块 | **单独向你申请**后再做（本计划已列迁移 059–063，仍需开工前点头） |
| 节点 | 任务拆解你确认后开工；每阶段（P0/P1/…）结束**停下来给你看**再继续 |
| 止损 | 同一手段连续 2 次失败 → 停下换路径并告知 |
| 仓库纪律 | Windows PowerShell 开发；Docker 验证走 WSL Skill；不碰 `.env` 密钥 |

**推荐执行方式**（三选一，开工时定）：

1. **本会话自做**（默认）：按 tasks 顺序实现，每任务完成后自检再下一项  
2. **Spec Kit `/speckit-implement`**：若要走仓库既有 specify 流程，可把本清单落入 `specs/014-*/tasks.md`  
3. **并行子代理**：独立任务（如前端壳/后端 skills）可分派，仍须单点集成与你节点确认
