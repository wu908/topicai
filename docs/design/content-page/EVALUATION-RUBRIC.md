# 内容页六版方案 · 评审评分卡

> 用途：对 V1–V6 六版原型做**同一把尺子**的横向评审，产出最终选型（单选或组合）。
> 依据：`docs/research/content-page-design-methods.md`（外部方法论，含来源链接）、
> `DESIGN.md` v3（产品设计权威）、`docs/reviews/user-acceptance-test-2026-09-19.md`（实测问题）。
> 说明：本评分卡**不预设结论**。权重可在评审时调整。

---

## 1. 权重总览

| 组 | 条目数 | 权重 | 说明 |
|---|---|---|---|
| A 结构性硬规则 | 10 | 40% | 有明确外部来源；违反即为缺陷，不是偏好 |

评分：每项 0–5 分（0 = 违反/缺失，3 = 及格，5 = 优秀且有证据）。

## 2. A 组 · 结构性硬规则（40%）

| # | 判据 | 为什么 | 来源 |
|---|---|---|---|
| A1 | **状态不得只靠颜色编码** —— 必须 图标 + 文字 + 颜色 三者同时变化；禁止裸色点 | NN/g 实测：颜色+图标比纯文字快约 37%；纯色点对色盲用户不可用 | [NN/g](https://www.nngroup.com/articles/visual-indicators-differentiators/) |
| A2 | **默认扫描列表用 行/列表，不用卡片** —— 卡片属于展示性场景，工作队列是扫描任务 | Ant Design 把卡片列表归为「展示性，无特定阅读顺序」；卡片还吃掉状态所需的纵向空间 | [Ant Design](https://ant.design/docs/spec/data-list-cn/) |
| A3 | **同一屏只有一个主动作按钮** | 多个主动作并列会让用户无法判断主次 | [Carbon 空态](https://carbondesignsystem.com/patterns/empty-states-pattern/) |
| A4 | **四态分离：loading / empty / error / data**，绝不在请求进行中渲染「没有数据」 | NN/g：加载中显示空态会被记为「特别有害」，用户会严重丧失信任 | [NN/g 空态](https://www.nngroup.com/articles/empty-state-interface-design/) |
| A5 | **骨架屏必须是内容形状**，不是只有页头页脚的框架 | 框架式骨架等同于 spinner，教不会用户任何东西 | [NN/g 骨架屏](https://www.nngroup.com/articles/skeleton-screens/) |
| A6 | **两栏布局只在 ≥840dp 使用；600–839dp 维持单栏** | M3 明确指出中等断点下的双栏高密度内容「会降低可用性」 | [M3 断点](https://m3.material.io/foundations/layout/breakpoints) |
| A7 | **列表栏宽度上限约 320–360dp**，宽度大头给工作区 | Carbon：页面宽度应给主工作表面；M3 supporting pane 固定 360dp | [Carbon](https://carbondesignsystem.com/components/data-table/usage/) |
| A8 | **工具栏 ≤5 个动作，超出进 overflow**；行内动作 <3 个时保持内联 | Carbon 的 toolbar / overflow 规则 | [Carbon overflow](https://carbondesignsystem.com/components/overflow-menu/usage/) |
| A9 | **移动端只保留 标题 + 状态 两个字段**，其余进详情 | Shopify `listSlot="primary"/"secondary"`：让表格退化为堆叠列表而不是横向滚动 | [Shopify](https://shopify.dev/docs/api/app-home/latest/patterns/compositions/index-table) |
| A10 | **筛选复杂度阶梯**：先 状态 tab + 搜索 + 排序；facet 面板仅在列表经常超过一屏后再上 | GitLab 1–5 复杂度阶梯；NN/g「先确立真实需求」 | [GitLab](https://design.gitlab.com/patterns/filtering/) |

**批量操作附加项（仅对含批量能力的版本评分，其余版本给满分）**

| # | 判据 | 来源 |
|---|---|---|
| A11 | 表头勾选框的作用域无歧义（**仅当前页**） | [Marigold](https://www.marigold-ui.io/patterns/user-input/bulk-actions) |
| A12 | 翻页/筛选/排序后**不静默保留**跨页选区 | 同上 |
| A13 | 存在批量选区时，**行内动作禁用** | 同上 |
| A14 | 批量按钮**动词命名**，危险项排在最后并视觉分离 | 同上 |

## 3. B 组 · 本产品专属约束（30%）

| # | 判据 | 来源 |
|---|---|---|
| B1 | **「下一步」必须与工作台内的「现在先做」同源**，不得两处给出不同答案 | 实测 F12 |
| B2 | **阶段与进度必须可扫读**（当前 10 种 `next_action` 渲染成同一种灰字 = 不可扫读） | 实测 F11 |
| B3 | **时间信息可见**（最近更新 / 观察窗剩余天数） | 实测 F11 |
| B4 | **隐私与授权的语义唯一且一致**（不得出现同一条素材一处「可发布类」一处「私密」） | 实测 F6 |
| B5 | **HumanGate 四决策（事实 / 公开范围 / 发布 / 长期经验）不可被批量或默认确认** | `DESIGN.md` §7 红线 4；[HAX](https://www.microsoft.com/en-us/haxtoolkit/library/) anti-14 |
| B6 | **至少两处披露 AI 来源与人工确认边界**，且不使用数字置信度（如「87% 确信」） | [PAIR](https://pair.withgoogle.com/chapter/explainability-trust/) |

## 4. C 组 · 体验质量（20%）

| # | 判据 | 检查方式 |
|---|---|---|
| C1 | **眯眼测试**：缩略后能否一眼看出「哪个需要我」 | 缩到 25% 看，主次是否成立（[NN/g 视觉层级](https://www.nngroup.com/articles/visual-hierarchy-ux-definition/)） |
| C2 | **一屏内可否完成三角决策**：它是谁 / 到哪了 / 要我做什么 | 不滚动、不点击 |
| C3 | **死白面积**：首屏是否仍有大片无信息区域 | 实测现状 2 个项目时约 450px 全空 |
| C4 | **空态质量**：是否说清「为什么空」+「下一步做什么」 | 对照现状（现状此项表现良好，须保持） |
| C5 | **与 `DESIGN.md` 一致性**：无 emoji 图标、无绿、圆角锁、冷调阴影、tabular 数字 | Pre-Flight §9 逐条 |
| C6 | **密度是否是「买来的」**：信息量 ÷ 空间是否合理，而非均匀灰底铺开 | [Ström](https://matthewstrom.com/writing/ui-density/) |

## 7. 评审时应当明确记录的三件事

1. **单选还是组合**：六版不是互斥的。例如「V2 的分组 + V3 的右栏预览 + V5 的排序」可能优于任何单版；评审必须明确最终取哪几版。

2. **哪些判据是硬门禁**：建议 A1、A3、A4、B1、B4、B5 为硬门禁——任何版本只要违反就直接淘汰，不进入加权比较。

3. **哪些结论缺乏外部证据**（来自调研的诚实声明，不要在评审中假装有据）：
   - 中国小红书创作者究竟偏好「按阶段分组」还是「平铺时间线」——**无研究可依，属于待验证假设**；
   - 「多少项目开始需要筛选」——**无有效阈值**，任何数字都是假设；
   - 多日、非阻塞的观察窗口等待如何在个人创作工具里表达——**方法论空白**，需要单独设计 spike；
   - `解决 / 分享 / 记录` 这组意图轴**没有任何设计系统先例**，需要产品自己定义图例。

## 8. 尚需产品决策的开放问题（评审前请先答）

1. 小红书是否强制要求 AI 生成内容主动标识？如是，「发布检查」是否新增 AI 声明项？（影响 B7 是否为硬门禁）
2. 内容页的第一用户任务是「挑一条继续」还是「盘一遍全部」？这决定 A2/A10 的取舍方向。
3. 是否接受内容页从「纯列表」变成「列表 + 常驻右栏」？右栏会占用工作区宽度。
4. 项目数量预期规模（10 / 50 / 200+）？A10 的 facet 门槛取决于此。
