## 1. 一句话结论

**六版不是六个并列选项，而是三种不同产品假设。** 按方法论判据，**V3（双栏总览）是最稳的骨架**，V2 的「按谁在等谁分组」应作为它的一个视图，V5 的工具条应在列表变长后叠加；**V1 的卡片泳道被方法论明确不利**，V4 的时间线更适合放进「周复盘」，V6 的聚焦与 V3 的常驻右栏在设计上互斥，需要二选一。

### 交叉验证结论（同一脚本、同一视口，六版一起测）

用一份统一脚本（`frontend/_tmp_verify.mjs`，临时工具，用后删除）在 1280×800 下逐个渲染并检测：

| 检测项 | 结果 |
|---|---|
| 悬浮球与**所有文字元素**的重叠数 | **六版全部为 0** —— F7 在六版里都真的被修掉了，只是修法不同 |
| 横向溢出 | 六版全部无 |
| emoji 图标 | 六版全部为 **0** |
| 文档高度 | V1 800 / V2 948 / V3 800 / V4 800 / V5 800 / V6 809 —— 均无大片死白 |
| `.btn-primary` 数量 | V1 **1** / V2 2 / V3 2 / V4 **5** / V5 **7** / V6 2 |
| 被裁切的文字 | 仅 V1 一处：筛选器标签「按意图筛选」被裁 |

**结论修正**：我最初把「V1 球在 x=80」「V5 球在 y=0」记为缺陷，**这个判断不准确**。实测两者与内容零重叠，各自用了不同办法避开遮挡。真正的问题是**它们改动了产品模型**（见下），而不是遮挡。

### 需要产品确认的两处偏离

1. **V1 把悬浮球改成侧栏底部的常驻槽位**（实测 `x=80`，位于侧栏 20–220px 之内）。代理自述这是**有意为之**：把球放进侧栏的文档流槽位，从而与所有内容元素零重叠，并加了「常驻助手 · 不遮挡内容」的说明。
   **判断**：零重叠是真的，但这**改动了产品模型**——`DESIGN.md` §6 定稿的悬浮球是「浮在内容之上、可随意拖动、堆叠贴附球体」的对话入口，不是侧栏里的一个固定挂件。这属于**需要产品确认的偏离**，不是可以直接采纳的修复。我最初把它记为「压在侧栏上」是错的，此处更正。
2. **V5 把悬浮球改停到页头右侧留白**（实测 `x=1170, y=0`）。代理自述同样是有意为之：把球绝对定位到页头 gutter，使其完全避开工具栏、表格与 CTA。
   **判断**：与 V1 同类问题——避开遮挡是真的，但把球从「浮层对话入口」变成「页头挂件」，同样是**对 `DESIGN.md` §6 的偏离**。且 1280×800 下球紧贴上边缘，观感像被裁切。需产品确认，不宜直接采纳。
3. **V6 侧栏页脚写着「AI 正常 · fake-llm」** —— `fake-llm` 是代理臆造的调试字符串。真实应用此处是「AI 正常 · 本地编排」。原型不应发明后端状态名。**已由我直接修掉。**

### 次要但影响观感

- **导航图标不统一**：V1 用 `⌂ ▦ ◫`、V4 用 `◆ ▤ ▥`、V5 用 `◈ ◔ ◌`、V2/V3 用「首字」（晨/架/收）、**V6 完全没有图标**。且 V5 把「晨报」写成「今日晨报」、V3 的「周复盘」图标塞了两个字「经营」并溢出 16px 槽位。原型应逐字对齐真实侧栏。
- **侧栏页脚数据各版自造**：V2「AI 助手在线 / 本周产出 2」、V3「AI 在线 · 已完成 2 次校验」、V4「AI 在跟进 5 个项目」、V5「AI 会话正常 / 本月产出 7」、V6「本周承诺 3 / 已发 1」。真实应用是「AI 正常 · 本地编排」。建议统一。

## 3. 逐版评估

### V1 · 状态泳道

**做得好的**：5 列对应 5 个生命周期阶段，列头带编号（01–05）、数量、一句话说明；每列底部有「产出 / 出口」图例，说明了该阶段的产物与离开条件——这是六版里**唯一显式回答「这个阶段什么时候算结束」**的。每张卡片带 5 段进度条与一个动作按钮。

**问题**：
- **A2 硬伤**：方法论把「卡片作为默认扫描列表」列为反模式——Ant Design 将卡片列表归为「展示性、无特定阅读顺序」，而这是状态驱动的工作队列。卡片还吃掉状态所需的纵向空间。
- **A9 移动端**：泳道在窄屏必须横向滚动，与「移动端只保留 标题+状态」的纪律冲突。
- 悬浮球改为侧栏常驻槽位（见上，属产品偏离而非遮挡）。
- 筛选器标签「按意图筛选」被裁切（交叉验证中 V1 唯一一处文字裁切）。

**定位建议**：不作为默认视图。若要保留，可作**可选「看板」视图**，仅在项目数 ≤ 15 时有意义。

---

### V2 · 下一步清单 ⭐

**做得好的**：六版里**最直接命中实测问题 F11/F12 的一版**。
- 分组直接回答「谁在等谁」：`需要你决定 3` / `等它准备 2` / `等观察窗口 1` / `已完成 1`，每组带一句组义说明。
- 每行以**动作短语领衔**（如「确认候选内容是否准确表达了你」），项目标题降为副信息——这正是把「下一步」变成一等公民。
- 「等观察窗口」组显式给出 `还剩 4 天` 与 `窗口 09-23 关闭`，回答时间可见性（B3）。
- 顶部一行汇总：`3 个等你决定 · 2 个等它准备 · 1 个等观察窗口`。
- **诚实标注**：切换器上写明「[按主题] 为原型占位，尚未接入数据」——不假装有未实现的能力。

**问题**：
- 只解决了分组，**没有检索**（无搜索/排序），需求 #5 仅部分满足。
- 文档高度 976px，`已完成` 组需滚动才能看到。

**定位建议**：**作为 V3 的一个视图模式（「按需处理」）直接采纳**，其分组语义与组义说明文字可原样复用。

---

### V3 · 双栏总览 ⭐⭐

**做得好的**：**综合最平衡，建议作为重构骨架。**
- 左栏 ≈360px（符合 A7 的 320–360dp 上限），宽度大头留给右栏。
- 左栏每行：**阶段名 + 5 段进度条 + 标题 + 意图胶囊 + 更新时间 + 「需要我」标记**——六版里单行信息密度与可扫读性最好。
- 左栏顶部：搜索框 + `全部 7 / 需要我 4 / 观察中 2` 过滤片（A10 的复杂度阶梯 3 级，恰到好处）。
- 右栏：5 步阶段步进器 + 目标句 + **一个主按钮 + 一句时长说明**（「约 2 分钟」）+ 关键事实（含来源「出自 9 月 12 日你的原话」）+ 观察窗 + 最近动态（AI 追问 → 你回答 → AI 生成候选的时间线）。
- 底部明写：**「列表里的下一步与工作台「现在先做」同源」**——这是对实测 F12 的正面回应。
- 右栏在无选中时给了「设计的占位」而非留白（符合方法论：No selection → designed placeholder pane）。

**问题**：
- **A1 未完全达标**：「需要我」是纯文字，不是「图标+文字+颜色」三编码；阶段与进度靠进度条+文字，尚可。（重构时必须补图标，这是硬门禁 G1）
- 断点纪律：1280 下成立，但 600–839dp 必须退化为单栏，原型的 CSS 注释里声明了退化方式，**需在重构时验证**。
- 悬浮球 (1200,720) 与右栏底部「打开完整工作台 →」距离很近，需留安全边距。
- **矮视口风险（代理主动上报）**：V3 把页面严格钳制在视口高度内（这正是「不用跳转就能盘完 7 条」成立的前提），代价是左栏内部滚动、右栏高度受限。在约 **703px 高的视口**下右栏会内部滚动，其页脚可能与悬浮球相遇。干净的做法是给右栏加 `max-height` 而不是继续硬钳。**重构时必须用 1280×703 及更矮档位验收。**

**定位建议**：**采纳为默认骨架。**

> **共享样式的两个坑（V3 代理发现，其余版本可能同样中招，重构时用真实组件可规避）**：
> 1. `.field` 是共享 CSS 里**全视口固定背景层**的类名——把它当普通字段类用在搜索框上，会把输入框整个抽出文档流。命名有歧义，重构时不要沿用这个类名。
> 2. `.main` 必须用 `height` 而非 `min-height`；否则 grid 行随内容增长、页面出现滚动，悬浮球的预留带被推出视口，球就落到内容上了。flex 子项还需 `min-height: 0`。

### V4 · 创作日志

**做得好的**：唯一以「发生了什么」组织的一版，读起来最像创作档案而非待办队列。
- 顶部汇总条：`进行中 5 / 待你处理 3 / 本周已发 1 / 已沉淀经验 1 条`。
- 周分组头带周范围与小结（`本周 09-14 → 09-20 · 2 条在写、1 条已发布、1 条待复盘`）。
- 事件行写明动作主体（`创建了项目` / `AI 产出了候选内容` / `补齐了 2 处事实缺口` / `AI 追问了一段缺失的经历` / `发布了`），并给出 AI 的依据（`AI 已推断为「教方法」，等你点头或否决`）。
- `待你` 胶囊把需要人的事件标出来。

**问题**：
- **A3 硬伤**：屏幕上同时出现 3–5 个深色主按钮（`确认内容目的`、`确认候选内容`、`补充一段真实经历`…），违反「每屏一个主动作」。
- **需求 #5 未满足**：完全无检索/筛选/排序，项目一多就找不到东西。
- 右侧留白约 170px（为悬浮球留的 gutter），在时间线这种窄栏布局里略显空。

**定位建议**：**不建议作为「内容页」默认视图**。它的价值在语境而非检索——建议评估把它作为**「周复盘」或项目详情内的活动记录**，那里正是「按周回看发生了什么」的真实场景。

---

### V5 · 分面工作台

**做得好的**：**能力最完整的一版，工具条设计是六版最好的。**
- 视图片带计数：`全部 7 / 需要我 3 / 观察中 2 / 已完成 1`。
- 两个分面下拉（`全部意图` / `全部阶段`）+ 搜索框带 `/` 快捷键提示 + **密度切换（紧凑 / 舒适）**。
- 真表格，表头 `标题⇅ 意图⇅ 阶段⇅ 进度⇅ 观察窗⇅ 更新时间↓ 操作`，**当前排序列有可见指示**。
- 行内副信息做得最细：`素材 3 条 · 已标 1 条事实待核`、`候选 2 版 · 等你选一版`、`采访提纲 4 问 · 未回答`、`敏感词 1 处 · 事实清单已核`——这是六版里**唯一把「这条项目卡在哪」写进列表**的。
- 批量栏：`已选 2 项` + 领域动词命名（`批量归档` / `导出清单` / **`改观察窗`**）+ `取消选择`。
- 页脚：`共 7 个项目，显示 1–7` + 每页 20 条 + 分页。

**问题**：
- **A3 严重超标**：7 个 `.btn-primary`，`操作` 列 6 个深色实心按钮，视觉主次消失。
- **A10 超前**：方法论明确建议先出「状态 tab + 搜索 + 排序」（复杂度 3），**facet 面板等列表经常超过一屏再上**。当前 7 个项目就上双分面，属于「因为能做所以做」。
- **悬浮球在 y=0**，被顶部裁切。
- 若保留批量：需按 A11–A14 补「表头勾选仅当前页」「翻页/筛选清空选区」「批量态禁用行内动作」的可视状态（原型未展示这些）。

**定位建议**：**不作为首版默认视图，但工具条与表格模式应作为第二阶段叠加**（当项目列表经常超过一屏时）。它的行内副信息文案质量最高，建议抽取到 V3 的列表行里。

---

### V6 · 今日聚焦

**做得好的**：
- 用一张克制的主卡回答「今天该做哪一件」，与产品既有的晨报哲学一致。
- **代理主动纠正了简报里的一个事实错误**：我给的示例理由「它是你唯一一条卡在等你自己确认的项目」与共享数据集矛盾（#1 与 #4 同样是人闸），代理替换为与数据一致的措辞，并同步改了副标题。这是正确的做法。
- **主动标注评分卡冲突**：A3（每屏一个主动作）与 V6 规格要求的「页头主按钮 + 主卡主按钮」并存相冲突，代理选择**上报仲裁而非默默绕过**。
- 悬浮球用结构性方案（`.wrap{max-width:840px}` 预留 gutter）保证不压内容，并用 DOM 矩形验证而非目测。

**问题**：
- **放弃检索**：无筛选/排序/搜索，需求 #5 只靠分组+时间序。
- **与 V3 在设计上互斥**：V6 用整屏聚焦，V3 用常驻右栏；两者都想要会互相削弱。
- 侧栏无图标、页脚 `fake-llm` 文案需修。
- 规模上限低：30+ 项目时紧凑列表不再可扫读。

**定位建议**：**二选一（V3 或 V6）**。若产品判断「减少决策疲劳」优先于「并行推进」，则 V6 胜出；否则 V3。**建议先做 V3**，因为 V3 的右栏可以承载「推荐的下一步」这层信息，等于在不放弃列表的前提下部分获得 V6 的价值。

## 4. 建议的选型（供你裁决）

**骨架：V3 双栏总览**，叠加：

| 来源 | 采纳什么 | 理由 |
|---|---|---|
| V2 | **「按需处理」分组视图**（需要你 / 等它 / 等观察 / 已完成）作为 V3 左栏的视图切换 | 直接回答「谁在等谁」，是六版中最强的默认排序语义 |
| V2 | 组义说明文字（如「下一步只有你能做：四个 HumanGate 决策与确认动作不接 AI 代劳」） | 把产品原则放进界面，而非留在文档里 |
| V5 | **工具条**：搜索 + 排序 + 密度切换，以及**行内副信息**（`素材 3 条 · 已标 1 条事实待核`） | 检索能力与「卡在哪」的信息，V3 当前缺失 |
| V5 | 第二阶段（列表常超一屏后）再上 facet 与批量 | 遵循 A10 复杂度阶梯，避免过度建设 |
| V1 | 各阶段「产出 / 出口」图例文案 | 唯一说清「这个阶段何时算结束」的资产 |
| V6 | `换一条` 式的**可推翻推荐**交互（若 V3 右栏承担推荐） | 保持「AI 只提议」，且避免 V6 与 V3 互斥 |

**暂不采纳为默认视图**：V1 卡片泳道（A2 不利、移动端差）、V4 时间线（A3 超标、无检索；建议改投「周复盘」）、V6 聚焦（与 V3 互斥，V3 右栏已覆盖其价值）。

**必须先修的硬门禁**（无论选哪版）：A1 状态三编码、A3 单一主动作、A4 四态分离、B1 下一步同源、B4 隐私语义一致、B5 HumanGate 不可批量。

## 5. 需要你先决定的四件事

1. **第一任务是「挑一条继续」还是「盘一遍全部」？** 这决定默认视图偏 V2/V6（挑）还是 V5（盘）。当前建议 V3 是因为它两者都勉强能承载，但如果你能明确，选型会干净很多。
2. **是否接受内容页从纯列表变成「列表 + 常驻右栏」？** 右栏会占用工作区宽度，且 600–839dp 必须退化为单栏。
3. **小红书是否强制 AI 生成内容主动标识？** 若是，「发布检查」需新增 AI 声明项，并保留「用户写的 / AI 提议的 / 用户接受的」来源记录——这会影响内容页要不要展示来源状态。
4. **项目规模预期（10 / 50 / 200+）？** 决定 V5 的 facet 与批量是首版就上，还是第二阶段。

## 6. 尚缺的证据（不要在这轮假装有）

- 中国小红书创作者偏好「按阶段分组」还是「平铺时间线」——**无研究可依**，属待验证假设。
- 「多少项目开始需要筛选」——**无有效阈值**，任何数字都是假设。
- 多日、非阻塞的观察窗口等待如何表达——**方法论空白**，需单独设计 spike。
- `解决 / 分享 / 观察` 意图轴的视觉图例——**无设计系统先例**，需产品自定。
