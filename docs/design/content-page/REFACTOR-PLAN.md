## 3. 交互规格（推荐方向）

### 3.1 默认视图：双栏

```
┌ 内容 ──────────────────────────────────────────────┐
│ 7 个项目在跑 · 4 个等你决定 · 2 个在等数据    [新建项目] │
├──────────────┬──────────────────────────────────────┤
│ [全部7][需要我4][观察中2]   │  番茄钟别在下班后补…   候选内容·2/5 │
│ 🔍 搜索标题或意图            │  目标：把「下班后补番茄」…          │
│ ─────────────────────────── │  ①意图 ②证据 ③候选 ④检查 ⑤观察     │
│ ◔候选内容 番茄钟别在下班后补…│  ┌──────────────────────────────┐  │
│   踩坑复盘 · 2/5 · 今天09:58 │  │ 确认候选内容（约 2 分钟）      │  │
│   ⌾需要我                    │  └──────────────────────────────┘  │
│ ◑证据采访 阳台辣椒终于结果了  │  关键事实 1 条 · 出自 9/12 你的原话 │
│ …                            │  观察窗 7 天                        │
│                              │  最近动态（时间线）                 │
│                              │  打开完整工作台 →                   │
└──────────────┴──────────────────────────────────────┘
```

### 3.2 四态

| 态 | 触发 | 呈现 |
|---|---|---|
| `loading` | 首次请求在飞 | 列表骨架（3 行内容形状）+ 右栏骨架；**不显示「暂无项目」** |
| `empty` | 请求成功且 0 条 | 「还没有内容项目」+ 一个主按钮 + 一句为什么 |
| `error` | 请求失败 | 中文错误 + 可点「重新加载」（**保留已有数据**，不清空） |
| `data` | 有数据 | 列表 + 右栏（无选中时右栏给**设计过的占位**，不是留白） |

### 3.3 断点

| 宽度 | 布局 | 说明 |
|---|---|---|
| ≥ 840px | 双栏 | 左栏 320–360px，右栏自适应 |
| 600–839px | **单栏** | M3：中等断点双栏高密度内容会降低可用性 |
| < 600px | 单栏 + 进详情页 | 列表只保留 **标题 + 状态**；返回键只在单栏出现，双栏不出现（规则 36） |

### 3.4 「下一步」同源（G4）

列表行的动作文案与右栏主按钮文案**必须来自同一个字段**（`next_action` 经同一张映射表）。
建议把 `nextActionLabels`（现位于 `ContentPage.tsx:99-110`）提到 `projectListModel.ts`，两处共用，并加**单测断言两处取同一个 key**。

## 6. 风险与回滚

| 风险 | 缓解 |
|---|---|
| 双栏在 1280 下挤压工作区 | 左栏硬上限 360px；先在 `1280/1024/768/375` 四档截图验收 |
| `ContentPage.test.tsx` 36 KB 断言大面积失效 | 先跑基线，记录失败清单，逐条决定「改断言」还是「改实现」，不允许成批删除 |
| 现有 E2E（`intent-driven-loop.spec.ts`）依赖旧 DOM | 先跑一遍拿到基线；本轮只保证它继续绿 |
| 引入分组后性能 | 7 条数据无影响；列表超 100 条再考虑虚拟化（本轮不做） |

**回滚**：全部改动集中在 `ContentPage.tsx` / `ContentPage.css` / 新增 `features/content/*`，`git revert` 单次提交即可还原。
