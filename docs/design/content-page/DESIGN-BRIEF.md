# 内容页重设计 · 设计简报（Design Brief）

> 目标页面：`/content`（内容页，内容项目列表）
> 依据：`DESIGN.md` v3（唯一设计权威）、`docs/reviews/user-acceptance-test-2026-09-19.md`（实测问题）、`docs/research/content-page-design-methods.md`（外部方法论）
> 产物：6 版可对比的静态原型（`v1.html` … `v6.html`）+ 共享样式 `lumen-prototype.css`

---

## 1. 为什么重设计（实测证据）

来自 2026-09-19 全量用户测试，内容页（`/content`）被判定为全站信息架构最弱的一屏：

| 问题 | 证据 |
|---|---|
| F11 信息量不足、无法扫读 | 每行仅「标题 + 意图标签 + 右对齐灰色小字」。右对齐文字是 `nextActionLabels[next_action]`（`ContentPage.tsx:99-110`），共 **10 种**取值，全部渲染成同一种无色彩/无图标/无分组的灰色文字 |
| F11 无进度 | 工作台里有「进度 · 2/5 步」，列表里完全看不到 |
| F11 无时间信息 | 无创建时间、更新时间、观察窗截止 |
| F11 无检索能力 | 无筛选、无排序、无搜索、无分组、无归档视图 |
| F11 空间失衡 | 2 个项目时下方约 **450px 全空** |
| F12 两处「下一步」互相矛盾 | 同一项目：列表说「锁定发布意图」，工作台说「现在先做：确认候选内容是否准确表达了你」 |
| F5 无加载态 | 数据返回前主区**完全空白**（实测 3–4 秒），违反 DESIGN.md §9.9 |
| F18 截断无省略号 | 长标题句中硬截断 |
| F7 悬浮球遮挡 | 悬浮球固定右下 80×80，遮挡右栏控件 8–9% |

**保留不动**（本轮测试中被验证为优秀，不得推翻）：
- 「AI 先推断 → 单点追问 → 可一键否决」（`/content` 新建项目流程）
- 「AI 只提议，人确认」的四决策 HumanGate
- 空态文案质量（明确说明「为什么空」+「下一步做什么」）
- π 形灯框 + 独立输入泡的对话形态

## 2. 必须被设计解决的 6 件事

每版原型都必须能回答：

1. **这个项目现在在哪个阶段？** —— 阶段必须可扫读（视觉编码，而非一段灰字）
2. **现在需要我做什么？** —— 下一步动作必须是一等公民，且与工作台内的「现在先做」同源
3. **它走到哪一步了？** —— 进度可见（n/5 或阶段刻度）
4. **它多久没动了 / 观察窗还剩几天？** —— 时间信息可见
5. **我怎么在一堆项目里找到某一个？** —— 至少有分组或筛选之一
6. **空的时候这一屏看起来像什么？** —— 不允许出现大片死白

## 4. 六版方向（每版一个独立 HTML）

| 版本 | 名称 | 核心主张 | 主要解决 | 主动放弃 |
|---|---|---|---|---|
| **V1** | 状态泳道 Stage Board | 横向泳道按生命周期阶段分列，卡片随阶段推进 | 阶段可扫读、进度可见、死白消失 | 高项目数时要横向滚动 |
| **V2** | 下一步清单 Next-Action Queue | 列表按「谁在等谁」分组（需要你 / 等它 / 等观察），每行以动作领衔 | 下一步一等公民、与工作台同源 | 弱化「按主题浏览」 |
| **V3** | 双栏总览 Master–Detail | 左密集列表 + 右常驻预览面板，选中即看详情，免跳转 | 减少进进出出、信息密度 | 窄屏需退化为单栏 |
| **V4** | 创作日志 Timeline Journal | 按周分组的纵向日志，记录「发生了什么」 | 记录型意图、复盘语境、死白消失 | 快速定位某个项目变慢 |
| **V5** | 分面工作台 Faceted Table | 真表格：可排序列 + 保存视图 + 密度切换 + 批量操作 | 检索、排序、规模化管理 | 首次使用的温度感 |
| **V6** | 今日聚焦 Focus Hero | 顶部一张「今天该做的那一件」主卡 + 下方紧凑清单 | 决策疲劳、与晨报哲学一致 | 并行推进多项目时略慢 |

## 5. 每版原型的硬性约束

### 视觉（DESIGN.md 强制）
- 引入共享样式：`<link rel="stylesheet" href="lumen-prototype.css">`
- 背景三层：`.field` + `.orb`（渐变场 + 漂移光晕 + 点阵）
- 玻璃容器用 `.glass`；双重边框（外亮边壳 + 内核）
- 圆角锁：胶囊 9999 / 卡片 22px / 内嵌 15–16px
- 阴影只用冷调 `rgba(70,95,130,…)`，**禁纯黑影**
- **禁绿色、禁紫色渐变、禁霓虹按钮光**
- **禁 emoji 作图标**（用文字符号或简单 SVG）
- 数字一律 `tabular-nums`（用 `.num`）
- kicker 大写小字每 3 个区块最多 1 个
- 无装饰性圆点；中点 `·` 每行 ≤1

### 结构
- 左侧栏复用 `.sidebar` 结构（晨报/产出架/收件箱/急稿/周复盘/成长 + 管理组：内容/机会/素材/我的），当前页 `内容` 为 active
- 悬浮球用 `.ball`，但**必须避开内容**（不要默认压在右栏控件上）——这本身是对 F7 的修正
- 视口 1280×800 截图为佳，允许纵向滚动
- 页面标题区：`内容` + 一句副标题 + 主动作；副标题不得与主动作重复同意图 CTA

### 交互诚实性
- 所有可点击元素必须是「看起来会怎样，点了就怎样」
- 禁用态必须说明原因
- 不出现假输入框（静止的 `readonly` 输入框伪装成可输入）
- 空态必须说明「为什么空」与「下一步」

### 交付
- 单文件 HTML，内联该版本特有的 `<style>`，公共部分只用共享 CSS
- 文件顶部写注释块：版本名 / 核心主张 / 优化什么 / 放弃什么 / 移动端如何退化
- **不要修改应用代码**，只在 `docs/design/content-page/` 下新增文件
