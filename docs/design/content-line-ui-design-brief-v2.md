# 内容线 UI · 设计方案总结 v2（参考对齐）

> 目标：解决「空洞、字体不协调」；**不是**满屏信息密度  
> 参考：Linear 文档产品、NN/g 视觉层级、Figma 设计系统、Material 间距、impeccable Operate 工艺底线、仓库 `DESIGN.md` Lumen v3

---

## 1. 问题诊断（当前原型）

| 问题 | 原因 |
|---|---|
| 空洞 | 大 Hero 卡 + 两侧等高卡底部留白；行数少、栏高硬撑 `fill_container` |
| 字体不协调 | 标题 26/22、正文 14/15、标签 11–13 混用；中西文混排无统一字阶 |
| 气质散 | 玻璃卡套玻璃卡、阴影+圆角+胶囊多层叠加，主次不清 |

## 3. 设计方案（定稿口径）

### 3.1 字体与字阶（协调）

| 档 | 用途 | 规格 |
|---|---|---|
| **L1 标题** | 页标题 | 20px / 650 / 行高 1.25 |
| **L2 区块** | 分组标题 | 12px / 600 / muted / 字距 0.02em（不中英混用装饰字体） |
| **L3 正文** | 列表标题、正文 | 13px / 500 主 · 13px / 400 次 |
| **辅助** | 时间、计数、chip | 12px / 400 muted · 数字 `tabular-nums` |

**字体栈（唯一）**  
`"Inter", "PingFang SC", "Noto Sans SC", "Microsoft YaHei", sans-serif`  
西文/数字 Inter，中文系统黑体——**全站只此一套**，不混衬线、不混第二 UI 字。

**对比**：主文字 ink `#191E26`，次 `#454E5C`，弱 `#7E8898`；弱字仅元信息，不用于行动点。

### 3.2 间距与版式（充实不堆满）

- **8pt 栅格**：内距 12–16，组间 20–24，页边 16–20  
- **组内紧**（8–12）、**组间松**（20+）——靠分隔而不是空卡撑开  
- **主区满宽**：列表行通栏，去掉「卡中卡」双层圆角壳  
- **高度**：内容区 `min-height:100%`，用真实行数撑开；禁止等高空卡 `height:100%`  
- **Hero 压缩**：页头一行（标题 + 计数 + 主按钮），高度 ≈ 56–64px，不是海报区  

### 3.3 层级（一眼看出看哪）

1. 页标题 + 主 CTA（仅 1 个 contained）  
2. 分组标题 + 数量  
3. 行主文案（500–600）  
4. 元信息（muted 12）  
5. 次要操作（ghost / text button）  

### 3.4 组件

| 组件 | 做法 |
|---|---|
| 侧栏 | 宽 208–224；无大 brand 区；当前项浅底而非大胶囊满宽 |
| 列表行 | 高 44–52；左状态点/旗标 + 标题 + 右元信息；hover 浅底 |
| 确认卡 | 单层浅蓝左缘 2px 或浅底条，**不用**双层描边+阴影 |
| 输入 | 高 36–40；圆角 10 而非全圆（与卡片 12 协调） |
| Chip | 仅分类/状态，2–3 个/行，不用彩色堆叠 |

### 3.5 色（沿 Lumen，少强调）

- 背景 `#F1F4F9` / 面板 `#FFFFFF` 半透明或实色 **二选一统一**（建议主区实色白面板、侧栏玻璃）  
- 强调仅 `accent #2F6FED`（链接/选中/主 CTA 用 ink 更稳）  
- 状态：ok/warn 各一处，不进装饰  

### 3.6 布局骨架（四屏共用）

```
┌ Side 208 ─┬ TopBar 56 ────────────────────────────┐
│ 今日      │ 标题 · 副信息 · [主 CTA]               │
│ 内容      ├───────────────────────────────────────┤
│ 周复盘    │ 内容区（列表/双栏）撑满，无空卡底      │
│ 成长      │                                       │
│ 路径      │                                       │
└───────────┴───────────────────────────────────────┘
```

项目屏：`1fr / 360px` 双栏，中间 1px 分隔，不用两团独立阴影卡。

## 4. 对应改法（原型）

1. 重排 HTML：页头一行、实色面板、通栏行、统一 Inter+系统中文  
2. 今日：2 列列表「贴满」，行高固定，取消卡底大留白  
3. 项目屏：对话/产物贴容器，确认卡改条带  
4. 周复盘/成长/路径：表格化行 + 紧凑标签  
5. Pencil 四屏按同一 token 重画或改 padding/字号

## 7. 文案与 AI 语言规范（2026-10-11 补）

### 7.1 全站 UI 文案

| 规则 | 做法 |
|---|---|
| 无歧义 | 不用「处理/操作/确认」等空词；动词+宾语（「选一版文案」「填收藏数」） |
| 看得懂 | 默认给步骤时间（「约 2 分钟」）；能给出依据就给（「你已标可公开」） |
| 不吓人 | 不用「违规/禁止」除非真禁止；保护性规则写清「由你决定」 |
| 一致 | 同一概念同一词（路径 / 对账 / 确认卡 / 公开范围） |
| 可执行 | 空态说「为什么空 + 下一步」；错误说原因 + 怎么重试 |

### 7.2 AI 回复规则（全局助手 / 项目助手）

1. **先复述用户意思**（我理解成…），关键动作前再问一句是否要动手  
2. **短句、分点**；不堆术语；能给例子就给  
3. **建议不替你拍板**：发布 / 公开 / 长期经验 / 删除必须你同意  
4. **依据可见**：改稿、检查、推荐注明来源（素材、你的原话、样本）  
5. **听不懂就问**，不猜着改；一次只问一个关键问题  

### 7.3 两套 AI 身份（不得混用）

| | 全局 AI（悬浮球） | 项目助手（项目屏） |
|---|---|---|
| 名称/头像 | **用户可改**（名称 + 头像色） | 固定标识「项目助手」 |
| 范围 | 全站：想选题、整理素材、解释下一步 | 只服务**当前这条内容** |
| 出口 | 不替你改项目稿、不代确认 | 对话内联决策卡 |
| 文案 | 说清与项目助手分工 | 不聊全站杂事 |
