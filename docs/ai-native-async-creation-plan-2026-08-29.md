## 0. 结论与定位

把 TopicAI 从"陪同式引导流"重构为"**异步生产流**"：创作者随时把灵感和素材丢进收件箱就去休息；AI 在信任边界内自主生产出可发布的完整产出；创作者回来只做三件事——**挑哪条、什么时候发、每周花 1~2 分钟确认复盘**。

一句话原则（继承并深化既有宪法）：**收发散之权在人，守质量之责在 AI。** AI 的自主性体现在"准备到可发布为止"，人的不可替代决策收敛为四个：拾取（含事实确认）、公开范围、发布动作、周度经验确认。

**建序反转（本方案最重要的工程纪律）**：第一交付物不是完整系统，而是**可以被证伪的最小骨架**。陪伴话术、成长面板、探索面板全部后置到骨架被真实使用验证之后——这是本项目第三次面对"愿景先行"风险，前两次（两轮 Ponytail 审计）的教训直接写进建序。

## 1. 已锁定的设计决定（决议清单）

| # | 决定点 | 结论 |
|---|---|---|
| 1 | 自主权天花板 | AI 自主完成"从收件箱输入到通过发布检查的产出"；人保留：拾取（含事实确认）、公开范围、发布动作、周度经验确认 |
| 2 | 拾取契约 | **选择即确认**：点选产出=确认其事实清单（内联展示、逐条溯源到素材、可当场改、改后 AI 重渲染） |
| 3 | 复盘 | **周度批确认**：每周一次、一屏对照本周全部已发内容的判断 vs 实际，逐条确认结论或标"未知" |
| 4 | 陪伴边界 | v1 = 管家（五个开口时刻：晨报、拾取讲解、周复盘、里程碑、解释为什么），**无自由对话**；v1.5 = 单条产出内追问对话；全局聊天不做 |
| 5 | 每周时间预算 | ≤1 小时，保留较细的确认与编辑权；随能力成长应递减（养成回报曲线） |
| 6 | 机器不在线 | 开机补跑变体：打开时补产 + "昨夜产出"通知；不做系统级推送 |
| 7 | 素材授权 | 按素材类型细分授权；视觉能力默认仅对"可发布类"素材开放；私密/敏感素材不出本地边界 |
| 8 | 生产政策 | 周发布承诺 1~4 篇 × 每批 2~3 候选；**含 1 个探索位**（默认开启、信任面板可调 0/1） |
| 9 | 探索位规则 | 探索候选明示标注；落选**不扣能力信任**，只记偏好数据；漂移提议触发线=连续 3 次同类偏离 |
| 10 | 成长机制 | 成对里程碑：人的行为 ↔ AI 能力升级 ↔ 时间回报；等级可升可降、全审计、红线永不因成长松动；禁止装饰性等级 |
| 11 | 真实验证 | 当前无真实使用 → **先连续两周 dogfooding**，按 §6 三条证伪线判定方向 |
| 12 | 发布动作 | 永远手动（平台无开放发布 API + 宪法红线）；"什么时候发"=AI 提议时点+到点提醒+一键就绪 |
| 13 | 急稿通道 | 保留现有引导流作为同步挡位，与新异步挡共用一个入口，服务"现在就要发"的时刻 |
| 14 | 生产线程 | 带完整状态机与失败恢复；失败必须被管家说出，无静默死亡（无死路纪律延伸） |

## 2. 目标用户旅程

### 2.1 异步挡（主路径）

```
碎片时段（随时）           后台/补跑                  拾取时刻                  每周一次
──────────────           ──────────                ──────────               ──────────
灵感/素材/念头 → 收件箱 →  生产线程消化 →            产出架 → 挑一条 →         周复盘屏：
（10 秒，授权标记）        按缺口追问或标注待补        扫事实清单（40 秒内）      本周已发对照
                          → 产出 2~3 条含探索位       改或确认 → 定时间         → 逐条确认结论
                          → 通过结构健康预检          → 到点提醒 → 手动发布      → 经验入台账
```

各阶段契约：

| 阶段 | 用户输入 | AI 自主 | 用户决策 | 产出 |
|---|---|---|---|---|
| 收件箱 | 灵感一句话/图片/语音/文档/链接，带授权标记 | 归类、去重、素材隐私分级、入库 | 无（≤10 秒） | 生产触发 + 方向越权指令 |
| 生产 | 缺关键证据时收到一次性追问（可跳过→产出标"待补事实"但**不进产出架**） | 提取事实（溯源到素材）→ 归类意图/格式 → 起草标题+框架+正文 → 生成发布判断草案（受众变化/主要反应/观察窗口）→ 结构健康预检 → 组装产出 | 跳过或补料 | 2~3 条 Deliverable，含 1 探索位 |
| 拾取 | 无 | 陈列：事实清单+判断草案+提议时点+风险 | **选条=确认事实**；可展开编辑；定时；不选则一键归因 | ContentProject 实体化（含 ContentBrief.structure）、待发布 |
| 发布 | 一键复制/导出 → 小红书手动发 → 回贴链接时间 | 到点提醒；包已就绪 | 公开范围确认 + 发布动作 | 发布记录（Intent Lock 沿用既有机制） |
| 周复盘 | 截图批量上传（或标"拿不到数据"） | vision 预填指标；生成判断 vs 实际对照 | 逐条确认 Intent Outcome/观察任务/经验 | 已确认复盘 → 台账 → 下周生产更准 |

### 2.2 急稿挡（同步）

入口与收件箱同处一屏。点"现在就要发"→ 直接进现有引导流（建项目→给料→候选→锁定→发布检查），全程既有 HumanGate 不减。复用而非重建——当前引导流就是急稿能力的现成实现。

### 2.3 平凡日策略（三缺一不可）

- **冷启动**（第 1~2 周）：引导= Growth 历史导入（画像冷启动）+ 周承诺设定 + 授权矩阵勾选；信任全零 → 所有确认从严；产出保守（宁缺勿滥）。
- **空架日**：收件箱无输入时，机会引擎主动提案（画像/系列/受众问题驱动），管家晨报说明"今天没新产出，这是我基于你画像的 1 条提案"。
- **落选日**：不选=归因（太俗/选题不对/换换口味/时机不对）→ 偏好数据 + 探索燃料；产出 7 天未拾取自动降级回机会层，货架不堆积。

### 2.4 生产线程状态机（无死路）

```
queued → producing → ready →（7 天未拾取）→ expired → 降级回机会层
              ↓
            failed → auto-retry(≤2) → 仍失败 → needs_input（管家报告缺什么）
```

规则：限流（单次补跑消化至货架 <6 条）；每次生产写 AITrace（新 task_type：`inbox_production`）；失败重试不静默、不阻塞其他产出。

## 3. 与既有领域模型的衔接

**不动（宪法级）**：HumanGate 四个不可替代决策（事实、公开范围、发布、长期经验——事实门移位但不消失）；Evidence-Bounded Candidate；Intent Lock 不可变；追加写入；AITrace 全覆盖；`/api/v2` 唯一公开 API；无模型降级手动路径；additive migration。

**移位（关键裁决）**：
- **事实确认门 → 拾取时刻**。依据：事实来源是用户自己的素材（第一方），fabrication 风险主要来自 vision/转录误读，因此防线形态从"逐条问答"改为"内联可溯源清单+选择即确认"。误读的最后防线是：**缺证据的产出不得进入产出架**（比原文档二 §13.7 更严：在生产端拦截，而不是采纳后补）。
- **ContentProject 在拾取时实体化**。生产挂在轻量 Deliverable 上，不建项目——词汇表"Content Opportunity 被采纳后才成为项目"的语义保住："项目=用户承诺要发的一篇"由拾取触发。
- **意图确认 → 生产时 AI 归拟 + 拾取时确认**（Working Intent Confirmation 收敛进拾取屏）。

## 4. 陪伴与成长层（骨架验证后构建）

- **Companion v1**：五个开口时刻，每句话锚定真实系统状态（AITrace/信任台账/台账资产）；晨报=打开时呈现（不做系统推送）；解释为什么=点任何产出可追问其事实来源与结构理由。
- **Companion v1.5**：单条产出内的追问对话（范围锁死该条，可当场改稿重渲染）。
- **成长台账**：能力 × 等级 × 证据链；成对里程碑（示例：连续更新满 4 周 ↔ 反应判断升级 → 开始预填周计划；语音转写连续 10 次零纠正 → 语音类素材免逐条核对）；降级红色可见；**每级回报换算为"你每周省多少时间"**。
- **多样化三件套**：探索位（§1 决定 8/9）；收件箱即越权指令（本批生产服从最新灵感方向，画像让位）；漂移提议（连续 3 次偏离 → 管家提议更新画像，用户拍板）。

## 6. 分期建序与验收指标

### 证伪线（Phase 2 结束时判定，用户已确认）

1. **时间线**：每周实际维护 ≤1 小时，且第 2 周 < 第 1 周；
2. **产出线**：两周内 ≥3 条骨架产出被真实发布，且自评不尴尬；
3. **依赖线**：≥2 次"没有这个系统这条就不会发"的时刻（书面随手记）。
   → **两条以上不达：回炉方向，不堆功能。**

### Phase 0 — 地基与债务（部分已完成）

- ✅ 复盘文档入库；降级路径 E2E smoke 14/14；048→049 升级路径验证 5/5
- ⬜ **真实 LLM smoke**（阻塞：无凭据，需用户提供 base_url/key/model）
- ⬜ 容器复验（阻塞：WSL 已移除，需用户决定是否重装；否则记录等价验证结论）
- 验收：真实模型路径的 AITrace/降级/证据约束 smoke 全过

### Phase 1 — 步行骨架（异步最小闭环，陪伴皮肤全部不做）

后端：inbox_items（类型+授权标记+状态）、production_threads（状态机+限流+降级）、deliverables（含事实清单溯源 JSON+发布判断草案+提议时点）、拾取 API（复用 IntentConfirmationService/ContentProjectService，拾取建项目+注入 Brief.structure+证据创建）、周复盘批接口（包装既有 snapshot/blind review/observation）、埋点事件表（拾取耗时/接受/落选归因/发布数/周维护时长）。
前端：收件箱页（≤10 秒丢输入）、产出架+拾取屏（事实清单内联/改/认领/定时/落选归因）、急稿入口、周复盘屏、三线度量小面板。
骨架期即含：探索位默认规则（生产策略，无面板）、PublishCheck 结构预检（3~5 模板最小集）、失败状态机与朴素失败提示（不做话术）。
验收：三线数据可采集；既有 360+ 测试不降；新增覆盖率 ≥80%；无模型时全流程手动可走。

### Phase 2 — 狗粮期（2 周，用户执行）

每周记录三线数据；期中只做热修不做扩展。验收：证伪线判定；形成下一期优先级的书面结论。

### Phase 3 — 陪伴层

晨报、拾取讲解、周复盘叙述、失败报告话术、解释为什么（锚定 AITrace）。验收：拾取均时相对 Phase 2 下降；100% 产出可解释；失败 100% 被说出（测试断言）。

### Phase 4 — 成长层

信任面板、成对里程碑、探索位面板（0/1 可调）、漂移提议、表达偏好资产、降级可见。验收：信任升降全审计有测试；探索落选不扣分有测试；里程碑回报以时间呈现。

### Phase 5 — v1.5 与迭代 2

条内追问对话（v1.5）；ViralTeardown、AudienceQuestion、Hook/CTA 助手、模板库全量（原文档一迭代 2/3）。

## 7. 红线执行清单（逐条挂钩工程检查）

1. 不做预测/爆款评分 → 无新增评分字段；v2 source-integrity 扫描扩展至新表
2. 不自动发布/不操作账号 → 定时=提醒；发布动作永远人工（测试断言）
3. 不虚构 → 事实清单逐条溯源到素材；缺证据不进产出架（生产端拦截）
4. HumanGate 四决策不委托 → 门类型断言测试
5. `/api/v2` only → OpenAPI 检查延续
6. TDD 先行、覆盖 ≥80% → CI 门禁延续
7. additive migration → 迁移评审延续，历史 SQL 不可变
8. AITrace 全覆盖 → 新 task_type：`inbox_production`、`pickup_confirmation`、`weekly_review`
9. 无死路 → 状态机失败路径全覆盖测试；无模型手动路径 E2E 延续
10. 隐私 → 授权矩阵默认最严；私密/敏感素材不出本地视觉边界（测试断言）
