# 决策简报 + 流程契约（pilot11，D1）

## 决策简报（v3）

- **问题**：周复盘页面把 60 天数据标成「本周对照」，用户无法按周理解，复盘类指标口径不成立。
- **证据**：E1——`ReviewPage.tsx:43` 的 `listWeekly(60)` vs 产品方案 `:24`「本周全部已发内容」vs 后端 `async_loop.py:150` `days=7` vs `feature-inventory.md:1639-1642` 歧义项（基线 `ce7be40`）。
- **方案**：前端双窗口取数（7 天本周 / 60 天欠对账）；右栏结构与版式不变，仅修正副标题窗口标注与左栏空态 2 处文案；8–60 天已对照行不在本页展示（决策人接受）。
- **成功指标**：本周对照窗口正确率 100%；欠对账不丢 ≤60 天 pending；请求数 = 2 且失败不渲染半套。采集方式：组件测试断言。
- **kill criteria**：① 若用户要求「本周 = 自然周」→ 回 RG0 r3 重议范围（不做后端按周对齐的隐形扩范围）；② 若纳入「8–60 天已对照行展示」→ 回 RG0 r3 重议（新增 UI 需过设计门）。量化触发：连续 2 个自然周「本周对照」为 0 且用户提出按周口径异议。
- **被接受风险**：R1 8–60 天已对照行不展示（A9-20261031-02）；R2 多一次请求；R3 本周=滚动 7 天（U1）。
- **设计门**：沿用 `docs/design/content-line-prototype.html:1089-1154` 周复盘版式；不新增视觉元素；用户 2026-10-31 书面确认两处文案与沿用原型（`_sync/p2/decision-2026-10-31.md` D-03）作为决策人签字；历史无独立设计评审截图/签字 → A9-20261031-01（`docs/pm/review-window/02-a9.md`）。
- **决策**：做（T0/D1）；决策人：用户（项目所有者）；日期：2026-10-31。
