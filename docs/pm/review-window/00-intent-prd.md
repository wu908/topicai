# A0/A1 · 周复盘「本周」窗口口径自洽（pilot11，D1）

> 工件：A0/A1｜版本 v1 · 2026-10-31｜档位 **T0 / D1**
> 证据等级：E1（代码 + 产品方案 + 现有审查记录）
> 决策人：用户（2026-10-31 拍板 C1，窗口方案 = 7 天本周 + 60 天待回填）

## 1. 问题与证据

- **现象**：`frontend/src/pages/Review/ReviewPage.tsx` 用 `listWeekly(60)` 一次拉 60 天，但页面副标题和左栏标题写「**本周对照** {compared.length}」。
- **产品定义**：`docs/ai-native-async-creation-plan-2026-08-29.md` 决定 3——「每周一次、一屏对照**本周**全部已发内容」；后端 `GET /loop/weekly` 默认 `days=7`。
- **影响**：
  1. 用户看到的「本周对照」混入最多 60 天的数据，按周理解不成立；
  2. 后续「复盘完成率 / 周对照」类度量口径不成立（分子分母不是同一窗口）；
  3. `docs/reviews/feature-inventory.md` 已把「周复盘 7 天 vs 60 天」列为待决歧义，一直未决。

## 2. 目标用户与场景

- 目标用户：已发布内容、需要回填表现数据并做周度复盘的创作者。
- 场景：打开 `/review` → 左「本周对照」（最近 7 天发布的已对照内容）+ 右「欠对账」（≤60 天仍待回填的内容）+ 公式笔记。
- 用户价值：本周视图只含本周；超过一周的待回填仍有入口，不会丢。

## 3. 范围

**改动（前端为主，1 个页面 + 测试）**：

1. `ReviewPage.tsx` 两次取数：`listWeekly(7)`（本周）与 `listWeekly(60)`（欠对账）；
2. 数据切分：
   - 本周对照 = 7 天窗口内 `stage !== 'needs_snapshot'` 的行；
   - 欠对账 = 60 天窗口内 `stage === 'needs_snapshot'` 的行（每条显示发布日；7 天内的标「本周」，更早的标「待回填」）；
3. 副标题、左/右栏标题、chip 数量、空态文案按各自窗口准确表述（不再把 60 天数据叫「本周」）；
4. 组件测试：窗口切分、边界（第 7/8/60 天）、空态、加载失败；
5. 文档：`docs/reviews/feature-inventory.md` 中「周复盘 7 天 vs 60 天」歧义条目改为「已决：7 天本周 + 60 天欠对账」。

**非目标**：

- 不改后端接口签名、不改 `days` 默认值（后端默认 7 保持）；
- 不改复盘表单、确认动作、门/规则/模板；
- 不做视觉重设计（沿用现有 `lumen-*` 结构）；
- 不补造历史数据、不改既有 pilot 日志。

## 4. 成功指标与验收标准（可测试）

| # | 标准 | 怎么验 |
|---|---|---|
| A1 | 「本周对照」只来自 7 天窗口：mock 一条 8 天前且已对照的行 → 不出现在本周对照 | 组件测试 |
| A2 | 「欠对账」覆盖 ≤60 天 pending：第 8 天、第 60 天出现；第 61 天不出现 | 组件测试（mock 窗口） |
| A3 | 首次加载只发 2 个 weekly 请求（days=7、days=60），无重复请求 | 组件测试（mock 调用次数） |
| A4 | 文案自洽：副标题/标题/chip 不再把 60 天数量称为「本周」 | 快照/断言 |
| A5 | `tsc` / `eslint` / `build` 0；目标测试 + 全量 content 回归绿 | 命令输出 |

**成功指标**：本周对照窗口正确率 100%（A1/A2 用例）；无新增接口调用错误；页面加载请求数 = 2。

## 5. 设计门（D1 must-pass 6）

- 沿用已确认原型：`docs/design/content-line-prototype.html`「周复盘」（左：本周对照｜右：欠对账 + 公式笔记）。
- 本次不新增视觉设计，仅数据窗口与文案对齐；实施后 A5 附页面截图与 DOM 断言。

## 6. 风险与回滚

- 风险：多一次前端请求（7/60 各一次，可接受）；滚动窗口 vs 自然周的语义假设（见 §7）。
- 回滚：单列提交，`git revert <commit>` 即恢复。

## 7. 未知项（显式记录，不伪造）

- **U1**：本方案把「本周」定义为**最近 7 天滚动窗口**（与后端 `days=7` 一致），不是自然周（周一–周日）。若产品要求自然周，需要后端按周对齐 + 文案调整，范围变大，需另议。
- **U2**：发布超过 60 天仍未回填的项目会从页面消失（现状也是 60 天上限）。本次不改上限，记入 backlog 观察。
