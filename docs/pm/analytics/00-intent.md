## 二、要什么 / 为什么 / 约束（不加工）

- **要什么**：把前端已有的事件从「只进内存/自定义事件、没人消费」变成**可落库、可查询、可审计**的第一方事件链路；先覆盖内容列表 3 类事件，供产品指标与 RG3 验收使用。
- **为什么**：试点暴露「度量不可用」——没有消费端，主指标无法计算；没有事件表，发布后漏放反查也缺数据。
- **约束**：
  - **无直接标识符**：不采集姓名/邮箱/手机号/IP/UA/内容正文；但会存 `owner_user_id`（伪匿名标识符）+ `project_id` + 行为序列——按隐私口径属**伪匿名个人数据**，不是「无 PII」；内测允许，对外发布前须隐私复核（A9-20261030-01）。
  - 内测/单用户仓库场景，不引入第三方分析服务（GA/PostHog/Mixpanel）。
  - 不改变现有 UI 与业务流程；采集失败不得影响页面。
  - 必须能给 RG3/OG0 提供证据（事件可查、可回滚、可观测）。
  - **采集默认关闭**（`ANALYTICS_INGEST_ENABLED=false`）；启用前须用户对 A9-20261030-04 签字（RG0-r2 修订）。
  - 数据库变更走现有迁移机制（`backend/app/data/migrations/`，当前最新 059）。
