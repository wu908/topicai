# TopicAI 核心流程线框规格

**目标场景**：成长型创作者打开今日，看到基于当前 Observation 的主要行动，进入内容项目完成证据采访并形成候选 Brief。

本文定义信息层级与交互，不定义最终视觉风格。

## Flow A：今日 → 接受主要行动

### A1 今日

```text
┌──────────────────────────────────────────────────────────────────┐
│ 今天                         本周 1/2 篇              7月19日     │
│                                                                  │
│ 主要行动                                                         │
│ 验证“清单结构是否更容易被收藏”                                   │
│ 为下一篇内容补充一个真实案例，再生成 Brief                        │
│                                                                  │
│ 为什么现在                                                       │
│ 上一篇收藏 214，但只有一个样本，无法确认结构作用                  │
│ 依据  [上一项目] [Observation]            未知  2 项             │
│                                                                  │
│ [接受并进入项目]               [暂不做] [手动继续]                │
├──────────────────────────────────────────────────────────────────┤
│ 次要任务                                                         │
│ · 周五前回填“复盘方法”项目的 48 小时数据                         │
│ · 确认 2 条历史笔记提取的画像事实                                │
└──────────────────────────────────────────────────────────────────┘
```

交互规则：

- 首屏只能有一个实心主要按钮。
- 接受后创建/复用 NextBestAction，并导航到目标项目的 Brief 视图。
- “暂不做”要求选择简短原因；“手动继续”进入同一目标，不创建 AI 执行记录。
- 模型不可用时，主要动作仍显示，AI 准备内容替换为手动问题清单。

## Flow B：项目 → 证据采访 → 候选 Brief

### B1 项目工作台

```text
┌───────────────┬───────────────────────────────────┬──────────────┐
│ 项目时间线    │ 当前任务：补充真实案例             │ 项目依据     │
│               │                                   │              │
│ ✓ 机会        │ AI：你在哪一次周复盘中发现         │ 目标读者     │
│ ● 证据采访    │ “只列完成事项”没有帮助？           │ 职场1-3年    │
│ ○ Brief       │                                   │              │
│ ○ 创作        │ [输入真实经历...]                  │ 已确认事实 3 │
│ ○ 发布        │                                   │ AI推断     1 │
│ ○ 复盘        │ [确认这段事实]  [跳过]             │ 未知       2 │
│               │                                   │              │
│               │ 进度 2/4                          │ 素材  + 添加 │
└───────────────┴───────────────────────────────────┴──────────────┘
```

交互规则：

- 每次只问一个能填补明确 Evidence gap 的问题。
- 回答默认是待确认 Evidence；用户确认后才成为 `user_fact`。
- 跳过不会阻塞通用结构，但事实型完整草稿必须继续受限。
- 右栏明确区分用户事实、外部事实、AI 推断和已验证经验。

### B2 候选 Brief

```text
┌───────────────┬──────────────────────────────────────────────────┐
│ Brief 导航    │ 候选 Brief                                      │
│               │                                                  │
│ 受众问题      │ 受众问题  知道复盘重要，但坚持成本高             │
│ 核心承诺      │ 核心承诺  一个十分钟可执行的三步方法             │
│ 真实案例      │ 真实案例  第三周只记录完成事项，没有改变下周行动 │
│ 证据与未知    │                                                  │
│               │ 结构                                             │
│               │ 1. 失败现场  2. 三步方法  3. 下周实验            │
│               │                                                  │
│               │ [接受为 Brief] [逐项修改] [查看生成依据]         │
└───────────────┴──────────────────────────────────────────────────┘
```

接受 Brief 是 HumanGate。重新生成创建新候选，不覆盖已确认内容。

## Flow C：机会 → 创建项目

### C1 机会列表

```text
┌──────────────────────────────────────────────────────────────────┐
│ 机会                                             [来源筛选]       │
│ 当前可执行 3 个                                                   │
├──────────────────────────────────────────────────────────────────┤
│ 延续“每周复盘”系列：复盘为什么总变成流水账                       │
│ 来源  上一轮 Observation + 2 条历史评论                           │
│ 匹配  受众高 / 创作者高    素材准备  3/4                         │
│ 作用  稳定更新 + 收藏验证   风险  同质化中                        │
│ [查看依据]                                      [创建项目]       │
├──────────────────────────────────────────────────────────────────┤
│ 把一次失败复盘改写成案例                                         │
│ 来源  用户素材组合                                                │
│ 匹配  受众中 / 创作者高    素材准备  4/4                         │
│ [查看依据]                                      [创建项目]       │
└──────────────────────────────────────────────────────────────────┘
```

列表不显示爆款分或精确概率。默认排序必须可由来源、准备度和当前目标解释。

### C2 机会详情

```text
机会标题
├─ 为什么值得现在做
├─ 来源证据（可逐条打开）
├─ 目标读者与创作者匹配
├─ 已有素材与缺口
├─ 本轮要验证的判断
└─ [创建内容项目] [补充素材] [忽略并说明原因]
```

创建项目时继承 Opportunity、Evidence 和实验目标，不复制文本快照为无来源字段。

## 桌面与移动端优先级

| 内容 | 桌面 | 移动端 |
|---|---|---|
| 主要行动 | 居中主列，可同时显示依据 | 首屏完整显示，依据折叠 |
| 项目时间线 | 左侧固定 | 顶部阶段菜单 |
| 当前任务 | 中央主工作区 | 第一屏唯一主内容 |
| 证据上下文 | 右侧栏 | 底部抽屉 |
| 次要任务 | 主要行动下方 | 主动作完成后显示 |

## 状态覆盖

每个线框必须有：加载、空状态、部分失败、AI 超时、无模型、证据不足、版本冲突、未保存修改、离线恢复和权限失败。

## 视觉探索约束

三套视觉方向必须使用完全相同的业务场景和信息，差异只来自层级、布局和交互重心。不得通过增加假指标、假功能、假数据源或营销文案制造差异。
