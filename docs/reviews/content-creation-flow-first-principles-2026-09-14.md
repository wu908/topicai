# 内容创建流程的第一性原理审查与重构提案（2026-09-14）

> 触发：用户以真实用户身份走完「创建项目 → 工作台」，反馈"过程繁杂、局限高、
> 看不懂每一项是什么/为什么/怎么做、信息密度高、排版第一眼不知道看什么"。
> 用户自己的判断：**意图应该由对话拆解得到，而不是让用户选**；并给出参考项目
> `XBuilderLAB/cheat-on-content`（7k stars）与外部调研要求。
> 本文是该次审查的诊断与重构提案（不含实现）。

---

## 一、先把机制说清楚：现在这个流程实际在做什么

`backend/app/services/intent_orchestrator.py` 里的 `INTENT_CONFIG` 是整条链路的
承重结构——**意图标签决定四件事**：

| 意图 | 派生的下一个问题 | 要求用户提供的素材 | 预期读者反应 | 发布后观察信号 |
|---|---|---|---|---|
| 解决 | 你亲自解决过这个问题的哪一步最容易被忽略？ | 真实问题场景 / 本人使用的方法 / 一个结果或限制 | 收藏 / 关注 / 问题型评论 | 收藏、关注、提问型评论 |
| 分享 | 这段经历里，哪个瞬间改变了你的看法或感受？ | 真实事件 / 当时的感受或观点 / 形成这一理解的原因 | 共鸣评论 / 有质量的互动 / 关注 | 共鸣评论、互动质量、关注 |
| 记录 | 这次变化开始前是什么状态，现在最具体的变化是什么？ | 起点证据 / 过程片段 / 转折 / 当前结果 | 持续关注 / 追问进展 / 系列期待 | 完成度、回访读者、系列延续 |

**结论：意图不是一个"用户偏好"，而是系统的路由键。** 用户选了它，等于替系统
决定接下来问什么、要什么素材、复盘量什么指标——**而这些后果在选择的那一刻是不可见的**。

---

## 二、第一性原理诊断：四个根因

### 根因 1：把内部状态机当作请求用户输入的对象
3 个枚举（解决/分享/记录）是产品内部的数据模型词汇，不是创作者的心智模型。
创作者脑子里的话是：

- 「我做了个东西，想给人看」
- 「有人问我一个问题，我想回答」
- 「我刚经历一件事，想说两句」

**没有一个人会先想"这条内容属于解决、分享还是记录"。** 让用户做这个分类，等于要求
用户替系统做数据建模——这正是"看不懂各地方要填什么"的根源。

用户问「内容意图应该给出确定性的选项吗？」——**不应该**。它应该是系统推断出来的
判断，配上理由，让用户一句话纠正。

### 根因 2：用"抽象结论"当输入，而不是从具体材料里提炼
现在的必填项是「希望读者发生什么变化」——这是一个**结论**。而用户手上有的只是
"一个想说的东西"。要求创作者（无论新手还是成熟博主）凭空说出"我要让读者发生什么变化"，
等于把最难的抽象工作前置给了最没有上下文的人。

同一个抽象还出现了 **3 次**（创建表单、工作台意图确认、拾取面板），
而设计研究里明确写着 **never re-ask known information——重复提问会侵蚀信任**。

### 根因 3：分类法覆盖不了真实场景，且失败是"问错问题"而不是"报错"
用户举的例子是决定性的：**「假如我只是分享我创作的作品呢？」**

- 分类法里没有"展示作品"这一格；
- 用户只能选最近的"分享"；
- 选完之后系统问的是「**哪个瞬间改变了你的看法或感受**」；
- 而一条成果展示类内容**没有转折、没有顿悟**——用户被问了一个前提不成立的问题。

所以问题不只是"标签少一个"，而是**问题的前提由标签单点决定，标签一旦近似，
后续全部跑偏**。（第五轮我还记录过"零信息时 AI 硬猜意图"——同一个根因的另一面。）

### 根因 4：信息密度没有层级
工作台一屏同时呈现：内容意图标签 + 大标题 + 三栏（五阶段进度 / 编辑区 / 写作提醒）+
「AI 选择下一步」+ 「AI 依据 / 还不知道」+ 观察窗口建议 + 折叠的高级项。

每一项单独看都有道理，同时给出就是**没有优先级**。用户的描述"第一眼不知道看什么"
正是缺少视觉与信息层级的症状——这与第三/四轮已修的"字段折叠"是同一类问题，
但还没解决**版面层**的层级。

## 三、参考项目怎么做（必须参考项）

`XBuilderLAB/cheat-on-content`（7k stars, MIT）——同样是"把内容变成可校准实验"，
但**onboarding 形态与 TopicAI 完全相反**：

| 维度 | cheat-on-content | TopicAI 现状 |
|---|---|---|
| 首次进入 | `/cheat-init`：**6 个问题，一问一答，明确不批量提问** | 一张表单 + 一个下拉 + 多个文本框 |
| 时间预算 | 明说 ≤5 分钟（导入历史 ≤10 分钟） | 无预期管理 |
| 期望设置 | 直白告知"前 5 篇精度 ±50%"，并用 🔴🟠🟡🟢🔵 标 confidence，**不藏数字** | 无 |
| 关键输入 | **强烈建议导入对标账号**（3–5 条即可建立 anchor），而不是问抽象自我描述 | 让用户回答抽象命题 |
| 冷启动 | 明确**简化**：只要打分 + 一句话 bet，"不强求 bucket 数字（避免 false precision）" | 冷启动用户仍要走完整意图确认 |
| 受众画像 | **从复盘评论聚类派生**（`cheat-persona`），且**盲评阶段硬禁读** | 让用户填写 |
| 选题 | "AI 听用户讲 → 帮提炼角度 → 写一份 draft，**不是 dump 15 个候选让用户挑**"；`MAX_DEEP_DIVE_TURNS=4`（**反盘问上限**） | 无上限的多轮表单 |
| 反模式 | 明确列出"必须拒绝的请求"清单（如"凭感觉推荐选题"） | 无 |

**最值得抄的三件事**：
1. **一问一答，且有盘问上限**——深挖最多 4 轮，超过就收敛；
2. **用对标账号替代抽象自述**——用户说不出自己是谁，但能指出"我想做成这样"；
3. **画像从行为数据派生，不靠填写**——TopicAI 已经有复盘数据（盲评、真实表现、
   落选归因），完全具备派生条件，却仍在问用户。

## 四、设计侧的行业共识（外部调研）

- 每一个表单字段都在占用用户有限的工作记忆（NN/g）；**PLG 的"5 分钟规则"**要求
  尽快给出价值；
- **渐进式画像**四阶段：身份/资格 → 上下文/需求 → 深度/偏好 → 敏感信息；
  且"注册时的每一个字段都必须能证明自己的价值超过它带来的转化损失"；
- **首触只问 2–3 个问题**；优先"决策价值高"的字段，而不是"填起来方便"的字段；
- **置信度阈值模型**：<50% 观察、50–80% 确认、>80% 行动——**先推断，中等置信度才请用户确认**；
- 对话式 + 行为观察结合，可显著减少需要问的问题数；
- 一个常被忽略的事实：**RLHF 会让模型抑制澄清性提问（约 77%）**——所以"多问一句"
  需要在系统提示里被显式鼓励，否则助手会硬猜（TopicAI 第五轮实测的"零信息硬猜意图"
  正是这个现象的现场）。

## 五、重构提案

### 原则（五条）
1. **推断优先，确认其次**——系统能推断的绝不问；中等置信度时用一句话让用户纠正。
2. **一次只问一件事，且有上限**——单次深挖 ≤3 轮；到上限就出候选让用户改。
3. **问具体，不问抽象**——问"最近哪件事让你想说"而不是"你要让读者发生什么变化"。
4. **同一信息全产品只问一次**——已确认的读者变化、受众、目标不再重复索要。
5. **冷启动简化，成熟用户走短路径**——有历史数据的用户跳过确认，直接给候选。

### 改造 1：入口从「填表」改为「说一句 + 对话拆解」（最高优先）
- 一个新入口：**一个输入框**——"你想做什么内容？一句话就行"（可留空，留空则进 brainstorm）；
- AI 收到后：先给**一个**判断（这是什么方向的内容 + 为什么这么判断），再问**一个**
  信息量最大的问题；≤3 轮后直接产出第一版候选内容让用户改；
- 意图、素材清单、观察信号全部由 AI 推断后**呈现**给用户，用户只在不对时纠正。

### 改造 2：意图改为「推断 + 确认」，并补齐真实场景
- 用户路径里取消意图下拉（保留下拉仅作为"纠正"入口）；
- **扩展维度**：当前 3 类无法覆盖"展示作品/成果汇报/回应提问/日常记录"。关键是要把
  **"这条内容里有没有一个转折或顿悟"** 独立出来——因为 `share` 的默认问题
  （"哪个瞬间改变了你的看法"）恰恰假设存在转折，而成果展示类没有；
- 允许"我也说不清"作为合法输入（现在必填三选一）。

### 改造 3：「希望读者发生什么变化」改为从材料里提炼候选
- 不再让用户凭空写结论；AI 从素材 + 该用户历史复盘里提炼 2–3 个候选
  （例："看完想试一次" / "看完有共鸣" / "看完想追后续"），用户点一个或改一句；
- 全产品只问一次，后续环节（工作台、拾取面板）**只读不再问**。

### 改造 4：「哪个瞬间改变了你的看法」改为 AI 指认候选
- 用户已经把素材给了；AI 应从素材里找出 1–2 个候选瞬间请用户确认，
  而不是要求用户自己回忆并抽象；
- 该问题**由维度决定是否出现**（成果展示类不问转折）。

### 改造 5：对标账号导入（补 cold-start 的 anchor）
- 让用户给 3–5 个"我想做成这样"的账号或笔记；
- 系统从中提取：选题范围、结构习惯、读者反应基线 → 意图推断与候选结构立刻有依据；
- 这比让新手回答任何抽象问题都有效，且可直接复用现有 `materials`/`signals` 结构。

### 改造 6：版面信息分层
- 一屏只呈现**一件事**；五阶段进度收成一行细线（当前是显著的三栏之一）；
- 「AI 依据 / 还不知道」「写作提醒」默认收起，用"为什么这么问"触发；
- 排版上先给"现在做什么"，其余降级为可展开的次要信息。

## 六、建议的落地顺序（每步可单独回退）

| 批次 | 内容 | 为什么先做 |
|---|---|---|
| 1 | 改造 1 + 改造 2（对话式入口 + 意图推断确认） | 直接解决"看不懂、被迫选分类、问题跑偏" |
| 2 | 改造 3（读者变化提候选 + 只问一次） | 消除最刺眼的重复提问与抽象命题 |
| 3 | 改造 4（瞬间改指认） | 依赖改造 2 的维度 |
| 4 | 改造 5（对标账号） | 需要新数据模型，收益是 cold-start 质量 |
| 5 | 改造 6（版面分层） | 独立于逻辑改造，可随时插入 |

## 七、怎么验证改对了（可量化）

1. **首触到出第一版候选**：问题数 ≤3、时长 ≤5 分钟；
2. **从进入创建到成功创建**的完成率（当前未埋点，建议先补埋点再改）；
3. **意图被用户纠正的比例**：初期偏高是正常的，长期应下降——它衡量推断质量；
4. **同一信息重复索要次数 = 0**（读者变化、受众、目标各一次）；
5. **成果展示类内容不再收到"转折瞬间"问题**——用真实场景做验收用例。
