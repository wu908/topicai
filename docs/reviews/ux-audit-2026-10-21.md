# UX 体验审计 · 零基础自媒体用户视角（2026-10-21）

> 测试对象：线上环境 `https://1.13.251.252`（域名 `topicai.online` 备案中，暂用 IP 访问并忽略证书告警）。
> 方式：Playwright（Chromium，视为内置浏览器）真实注册/登录/操作，桌面 1280×900 + 移动端 390×844；
> AI 为线上真实模型（`deepseek-v4-flash-vision-exp`），另做了一次断网（路由拦截）验证。
> 临时账号已按隐私流程注销：线上 `users=3`、无该账号数据残留；截图全量在
> `browser-screenshots/ux-audit-2026-10-21/`，本报告只收录关键 12 张到
> `docs/reviews/ux-audit-2026-10-21/`。

## 0. 一句话结论

**内容页的主流程在"第一次需要用户拍板"的地方就断了**：确认卡类型标错、主按钮"同意"会把空回答提交并报英文 400，正确操作（点"改"补一句）没有任何提示；再叠加"新用户首屏显示没做过的数据""一批按钮点了没反应""界面里直接出现 solve / preparing / create_version 这类开发语言"，零基础用户很难走完第一篇。

## 2. P0：零基础用户走不下去 / 会误解的问题

### P0-1 确认卡类型错标，主按钮把空回答提交并报错

- 证据：创建内容后弹出"**确认卡 · 公开范围**"，内容却是"你踩过最典型的那个坑是什么？…"，按钮是 **同意 / 改 / 否决**。
- 实测点「同意」：页面底部出现英文原样错误 `answer must contain at least 10 characters of first-party detail`，卡内出现"这次没有保存成功，请重试。"（截图 `confirm-card-answer-error.png`）。
- 正确路径是点「改」→ 输入 ≥10 字 → 点「存」，但界面没有任何提示，零基础用户会以为「同意」就是继续。
- 建议：
  - 按 gate 的真实语义选类型：这类是"待补充事实"，标题应为「还差一个真实细节」而不是「公开范围」；
  - 主按钮改成「**补充回答**」，点击后直接在同一张卡里出现输入框（不要先点「改」）；
  - 「同意/否决」只保留给真正的决策卡（公开范围、发布确认、长期经验）；
  - 后端校验错误按用户语言返回（"再补一点你自己的真实细节（至少 10 个字）"），不要把英文和字段名透出；
  - 前端在提交前校验并禁用按钮 + 说明字数要求。

### P0-2 "发布前检查"禁用但没有任何解释

- 证据：项目处于"版本=草稿 / 当前没有版本"时，`运行发前检查` 按钮 `disabled=true`，无 title、无说明、无前置 CTA（截图 `publish-check-disabled.png`）。用户点不动，也不知道要先做什么。
- 建议：按钮下方/旁边给一行原因与操作，例如：
  - "还没有可检查的稿——先写一版稿（去「稿」）或确认候选（点确认卡）"；
  - 或直接给"去写第一版"按钮。禁用态要有可感知的原因（tooltip/行内文案），不能只有灰。

### P0-3 设置/我的里"数据权利"按钮是死的

- 实测：`导出…`、`申请删除…`、`配置模型…`、`管理权限…` 点击后无任何弹窗/变化（仅全局 AI 面板的 dialog 常驻被计入）。
- 但登录页承诺"数据随时可导出带走"，"我的"页也有"导出与删除"入口。对零基础用户这是信任问题，也涉及隐私合规预期。
- 建议：要么接通（导出走现有 `/data-export` 门槛流程；删除走 `/deletion` 门槛流程），要么明确标注"即将上线"并禁用 + tooltip，或先移除入口。

### P0-4 界面直接暴露开发者语言

| 位置 | 显示 | 建议 |
|---|---|---|
| 过程页 kv | 意图 `solve`、状态 `preparing`、下一步 `create_version` | 教方法 / 正在准备候选 / 生成第一版稿 |
| 内容列表左列 | `意图 1/5` | `第 1 步 · 确认方向` 或直接给"进度 1/5"的解释 |
| 路径初始值 | 我想做成 = `stable_publish` | "稳定更新：先把发布节奏跑通" |
| 路径页脚 | `读取：deterministic_fallback` | "读取方式：本地规则（这次没有用模型）" |

### P0-5 新用户首屏出现"没做过的数据"，可信度受损

- 证据：新账号 0 项目 0 素材 0 发布，但「今日」显示：`公式候选 1`、`探索位：清单体 vs 过程叙事 2/3 条`、`素材未引用（可挂在途草稿）`、`本周节奏正常 · 宁缺毋滥`；「待你定」里还有一条种子任务（截图 `first-run-home.png`）。
- 影响：用户会以为系统在编数据，或以为自己之前操作过。
- 建议：新用户展示真正的空态/引导（"第一篇还没开始：先写一句想发的"），种子内容要么不展示，要么明确标"示例"；探索位/公式候选在确实产生后才出现。

### P0-6 AI 断网时把 `Failed to fetch` 直接吐给用户

- 证据：拦截 `/companion/ask` 后，对话气泡显示 `Failed to fetch` + "未能连接模型"（截图 `chat-ai-offline.png`）。
- 同时侧栏仍显示"AI 已连接 · …"，状态与实际不一致。
- 建议：统一错误文案："模型暂时连不上，你的输入还在，可以稍后重试"；侧栏 AI 状态按最近一次调用结果降级，并给出"重试/手动推进"入口。

### P0-7 聊天建议与功能不一致

- AI 回复："要改正文标题请到右侧「稿」操作"。但实测「稿」页签只有正文 textarea，标题是只读文本（且标题就是用户原话），无法修改（截图 `project-screen-created.png`、`14-draft-saved.png`）。
- 建议：稿页加"标题"输入（可 AI 生成候选）；或把聊天文案改成"标题候选可以点一个让我写进稿"并提供落地按钮。

### P0-8 草稿保存状态不可信

- 实测：在「稿」里输入 → 失焦 → 仍显示"**有未保存修改**"；点「保存草稿」后没有成功提示（无 toast、无"已保存"）。（截图 `14-draft-saved.png`、`26-draft-save-button.png`）
- 影响：用户不知道稿到底存没存；网络失败时也没有可见反馈。
- 建议：保存中 → "保存中…"；成功 → "已保存 hh:mm"；失败 → 明确错误 + 重试；失焦保存要真的触发（排查 onBlur 是否被 MUI/受控逻辑吃掉）。

## 3. 内容页专项（本次重点）

### 3.1 空态：入口太多，重点不突出

- 现在同时出现：顶部「快速开始」、空态卡「去路径设定方向 / 贴参考，读方向」、「开始一条内容」输入框 + 「开始」。
- 对"想发第一条但不知道发什么"的人，相当于 4 个门，但没有一个说"先做这个"。
- 建议：一个主 CTA「**开始第一条**」（输入一句话）为主；其余收进"不知道怎么开始？"折叠区：盘点真实经历 / 贴 2–3 个对标账号。

### 3.2 列表：信息不足 + 统计重复

- 证据（截图 `content-empty-state.png`、`20-content-with-project.png`）：
  - 顶部 `内容 全部 1 · 需要我 1 · 观察中 0 · 已沉淀 0`；
  - 下面又来一行 `全部内容` + 同样四个 chips；
  - 行内：`意图 1/5` + 用户原话标题 + AI 问句（作副标题）+ 右侧"需要我"。
- 问题：
  - 没有"下一步该做什么"的可执行按钮（整行可点但不知道点了会怎样）；
  - 没有形态/状态/最近动作时间等可扫读信息；
  - "需要我"既是行内 chip 又是筛选，语义混；
  - "意图 1/5"是内部阶段，新手无法理解。
- 建议：
  - 顶部只留一行统计；chips 只做筛选；
  - 行结构：`AI 命名/标题` + `形态 · 状态 · 时间` + `下一步：<动作> [按钮]`；
  - 按"想发的 / 在途 / 已发"分组（或至少可切换视图）；
  - 空的"需要我"给一句"为什么需要你"（例如"还差一个真实细节才能继续"）。

### 3.3 项目屏：结构重复、信息错位

- 双份阶段条：对话区顶部一排 `意图/证据/候选/检查/观察`，右栏"过程·结果"里又一行同样的 5 段；两处都像页签，但实测**点击"证据"页面无变化**（DOM 里是 `span.st`，不是按钮，截图 `87-stage-pill-click.png`）。
- 当前高亮"意图"，但屏上真正发生的是"AI 在问一个坑"——阶段与内容不对应。
- 过程页 kv 有硬编码/假数据：「路径 效率实验 · 未偏离」；「素材 已挂 1 件」在新项目上也显示，实际未关联任何素材（全库素材数被当成项目素材数）。
- 建议：
  - 只保留一条阶段指示，改成"人话流程条"（例如：想清楚 → 找素材 → 写初稿 → 发前检查 → 观察），当前步高亮并配一句"现在做：…"；
  - 过程页只放可核对的事实，去掉硬编码路径和"已挂素材"的误导统计；
  - 右栏页签固定在顶部，不再叠加第二排阶段。

### 3.4 稿页：不像"稿"，更像一个文本框

- 标题不可编辑（P0-7）；正文初始就是用户原话，不是 AI 草稿；"锁定预览 / 有未保存修改 / 保存草稿"三件套状态弱（P0-8）。
- 建议：标题 + 正文都可编辑；显示字数/预计发布形态；提供"AI 起草/润色"入口；保存状态常驻可见；没有版本时给出空态说明"确认上面那张卡后我会先写一版候选"。

### 3.5 发布包/视频包

- 发布包：标题仍是用户原话；发前检查禁用无解释；"发布时机：先锁定发布意图"没有跳转/说明。
- 视频包：文案诚实（"还缺：…"），但**没有"去素材/挂素材"的操作**，用户只能自己去素材页再回来。
- 建议：发布包把"前置条件 → 现在能做什么 → 发布后做什么"三段写清；视频包缺口行加"去素材匹配"按钮；一键把素材关联到本项目。

### 3.6 项目对话

- 首次进入只有一条欢迎语 + 大块空白，没有"AI 正在准备候选稿"的进度/骨架（状态只在 kv 里以 `preparing` 出现）。
- 建议：AI 生成期间显示"正在准备候选内容…（约 10–30s）"和取消；生成完自动把候选卡/稿推到用户面前。

## 4. 其他页面

### 今日

- 「快速开始」面板（截图 `today-quick-start.png`）本身清楚，但：
  - "只记下来"在输入前禁用，无解释；
  - "立成内容"与内容页的「开始」重复；
  - 面板里没有说"记下来之后去「想发的」看"。
- 「待你定」两条记录（`候选` / `待定`）看起来像同一个问题，用户分不清差别；"稍后"点击后会弹出"今天先不做 / 取消"，交互是对的，但主按钮"去处理"没有说明处理什么。
- 建议：候选/待定统一成"待你补充"与"待你拍板"两类；每行给一句"点了会做什么"。

### 素材

- 表单可用；保存后出现 `私密 · 仅本地` + chip `私密` 重复；`仅本地` 语义不清（是浏览器本地还是账号内？）。
- "删除"没有二次确认（高风险操作，本次未点，建议补确认/撤销）。
- 建议：隐私标签只出现一次并给解释；删除走确认或软删除；"复用到项目"在没有项目时明确置灰原因。

### 路径

- 初始 `我想做成 = stable_publish`（P0-4）；保存后正常。
- 探索位/对标文案基本清楚；"读取：deterministic_fallback"技术化。
- 建议：默认值全部人话；技术信息收进"说明"。

### 成长 / 周复盘

- 成长页对零基础用户信息量偏大：能力台帐 4 项（候选确认/发布前检查/长期经验写入/观点提炼）+ 里程碑 + 信任说明；术语（候选确认、长期经验写入）没有一句解释。
- 周复盘空态清楚。
- 建议：成长页首屏加一句"这里记录你越用越准的证据，不影响你现在发内容"；每项能力加一行"怎么获得"。

### 设置

- 好用：产品/全局 AI/项目助手/记忆/隐私分段；每周目标 1–7 正确；名称、头像、agent.md 保存可用。
- 问题：
  - 「模型与接口 / 配置模型…」「全局操控范围 / 管理权限…」是死按钮；
  - agent.md 长文本域没有可见 label（只有 aria），用户不知道这块是什么；
  - "已保存"只在右上角小绿字，易错过；
  - 7 个"每周 N 条"作为原生 select 一次展开，阅读负担大（可接受，但可改成 1–2/3–4 这类分段或步进器）。
- 建议：死按钮按 P0-3 处理；文本域加可见标题；保存反馈统一成 toast/行级状态。

### 我的 / 全局 AI / 登录

- 我的：同一件事有三个入口（打开设置 / 全部设置 / 更多管理），可以合并。
- 全局 AI：对话体验不错；但"建议先记进想发的"没有落地动作（用户会以为已经记了）；面板刷新后历史不保留（建议确认是否符合预期）。
- 登录：简单可用；"你的姓名"建议改"昵称（怎么称呼你）"；页面未见"忘记密码"入口。
- 页面标题 `TopicAI - 小红书内容操作系统` 偏窄：如果产品面向多平台自媒体，建议改成"自媒体内容创作系统"；若只做小红书则保留。

### 移动端（390×844）

- 底栏 5 项（今日/内容/周复盘/我的/更多）每项 74px、间隔紧；截图里"周复盘"与"更多"视觉拥挤（几何上未重叠，但字距过满）。
- 内容页筛选 chips 换行 3 行，"全部内容"被断成"全部内 / 容"；搜索框占满一行后行内容被压缩。
- 浮动球在右下，遮挡列表尾部/卡片操作（素材未引用、去素材附近）。
- 建议：底栏只保留 4 个一级入口 + "更多"；chips 横向滚动不换行；浮动球上加安全区或可收起。
