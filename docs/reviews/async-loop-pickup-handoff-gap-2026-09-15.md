# 异步循环实走：认领不交接（2026-09-15）

> 触发：以用户身份走核心闭环的后半段（产出架 → 拾取 → 工作台 → 发布 → 复盘）。
> 用户当前说"继续"，本轮按"先修一处、再把闭环走完、出报告"执行。
> **本文记录已修的与已发现的；闭环尚未走完，未走部分见第六节。**

---

## 一、走查方法（以及两个方法坑）

用仓库自带的 Playwright 无头浏览器（`frontend/scripts/loop-step.mjs` 等临时脚本）驱动本地实例，
数据由 API 造（3 条真实素材 → 真实模型消化 → 2 条产出）。

**坑 1（会误导结论）**：应用主内容是**内部滚动容器**，`page.screenshot({fullPage:true})` 拍不到
折叠线以下的部分。我因此一度以为"悬浮球压住了按钮行"——用 `elementFromPoint` 命中测试才发现
完全没重叠（球在 x=1156–1236，按钮在 x≈799）；元素截图会把 fixed 定位的球一起拍进来，是假象。
**坑 2**：IAB 后台标签的渲染被节流，`requestAnimationFrame` 不触发 → Playwright 的"元素稳定"
检查永不通过 → **点击与截图都会超时**。所以 IAB 里点不动按钮不一定是产品问题，别据此下结论。

## 二、已修：拾取面板要你把系统刚写好的话再打一遍（PR #107）

产出里 `judgment.audience_change` 已经写好「读者能判断出：与其追热点卡选题……」，拾取面板上方
把它显示成「发布判断草案」，**下方那个决定「认领」可用与否的必填框却是空的**。

根因很窄：点卡片会预填（`AsyncLoopPage` 第 232/254 行），但右栏在加载时**默认就展示第一条**
（`?? deliverables[0]`），这条路径没有预填；于是默认视图显示着一份它自己不肯接受的草案，
意图还停在硬编码的 `'solve'`——**产出若是分享/记录，预选意图本来就是错的**。

同屏另外两处：意图选中态只靠一点明度差表达且**没有 `aria-pressed`**；确认框是固定 48px
**单行**输入，四五十字的一句话被截断（"确认"看不到全文）。
三处都已修并反向验证（撤掉预填 → 两条新测试红）。

## 三、主要发现：认领只搬了三个字段，产出里做好的东西全部留在原地

`PickupService.pickup` 建项目时只写入 `title / content_intent / audience_change`。
产出里那版**已经生成好的正文、大纲、以及"逐条可溯源的事实"**没有交给项目。
实测该项目的库内计数：

| 关系 | 期望 | 实测 |
|---|---|---|
| `content_versions`（草稿版本） | ≥1（产出已有标题/正文/大纲） | **0** |
| `material_usages`（源素材挂载） | ≥1（事实带 `source_inbox_id`） | **0** |
| `evidence_items`（项目证据） | ≥1（卡片承诺"事实已溯源"） | **0** |

代码侧佐证：`deliverables.picked_project_id` **只有一个读者**——`async_loop.py:572` 的幂等重放分支
（用于返回已建项目）。也就是说这条外键建好之后，**没有任何下游用它把草稿取回来**。

### 四个可见症状

1. **承诺断裂**：产出架卡片写着「事实 ×1 已溯源」，认领后项目里事实数为 0。
2. **做好的一版作废**：工作台「写作草稿」区显示「完成上面的第一步 / 你的笔记草稿会出现在这里」，
   而系统在他自己的素材上刚写好的那版草稿**在项目里看不见、也用不上**。
3. **文案与来路不符**：工作台开场写「先给出一个模糊想法，AI 会帮你找到这条内容的目的」——
   可用户是**刚从产出架认领了一条成品**，不是从模糊想法起步。
4. **溯源断链**：源素材没挂到项目（`material_usages=0`）。而 R1 特意把"素材经 `material_usages`
   进溯源链"做成了「开始一条内容」的默认行为——**认领这条路径漏了同一件事**。

### 为什么这条比第二节那处更要紧

它不是文案或对齐问题，是**核心循环的一次交接失败**：消化器产出的一切（草稿/大纲/事实/素材链接）
只在产出架上存在，用户点「认领」之后就从项目的视角消失了。用户随后被要求"补一个真实信息"才能
"让 AI 准备候选内容"——**等于把已经做完的一步再做一遍**。

## 四、建议修法（三件，都是"把已产出的东西交过去"）

1. **挂素材**：认领时按 `facts[].source_inbox_id` 把源收件箱素材经 `material_usages` 挂到项目
   （复用 `project_start._attach_material` 已有的做法与私有默认）。
2. **种首个版本**：把产出的 `title/body_text/outline` 写成项目的第一个 `content_version`
   （`change_origin` 标注来自产出），工作台的草稿区因此一进来就有东西。
   - 设计判断：种了版本之后，工作台那个"你亲自解决过……最容易被忽略"的通用问题**是否还需要问**？
     我的建议是**保留但降级为可选**（草稿已在，用户随时可以补细节），而不是继续作为硬门槛挡住
     后续步骤；这与 R2 给「开始一条内容」做的"有推断问题就优先用它、别重复问"是同一原则。
3. **文案认来路**：工作台开场按项目是否有草稿分叉——有草稿时说"这条已经有初稿，你可以先改"，
   没有时才说"先给出一个模糊想法"。

## 五、验收基准（修完要能验的）

- 认领后 `content_versions ≥ 1`、`material_usages ≥ 1`，且草稿正文与产出一致
- 工作台首屏能看到那条草稿（不是"完成上面的第一步"）
- 产出架卡片承诺的「事实已溯源」在项目里成立（证据条目 ≥1）
- 有草稿时不出现"先给出一个模糊想法"这类与来路矛盾的文案
