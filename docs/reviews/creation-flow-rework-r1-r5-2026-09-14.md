# 第七轮 · 创建流程重构 R1–R5（2026-09-14）

> 触发：用户以真实用户身份走完「创建项目 → 工作台」，反馈"过程繁杂 / 局限高 /
> 看不懂每项是什么为什么怎么做 / 信息密度高 / 排版第一眼不知道看什么"，
> 并要求：从资深 AI PM + 第一性原理分析、参考必读项目 `XBuilderLAB/cheat-on-content`、
> **开始修正且每一步都要按用户视角反复琢磨视觉与交互**。
> 结论：**R1–R5 全部落地并经线上实测验证；对照参考项目还剩 2 项结构性工作（见第五节）。**

---

## 一、诊断（已入仓：`content-creation-flow-first-principles-2026-09-14.md`）

四个根因，每个都落到代码：

1. **意图枚举是系统路由键却被当成用户决策**。`INTENT_CONFIG` 里意图决定「下一个问题 /
   需要哪些素材 / 预期读者反应 / 发布后观察信号」，而用户在选它时看不到这些后果。
2. **用抽象结论当输入**。「希望读者发生什么变化」是结论，用户手上只有具体材料；
   同一个问题全产品问了 3 次（创建表单 / 工作台 / 拾取面板）。
3. **分类法覆盖不了真实场景**。用户举的例子是决定性的：「假如我只是分享我创作的作品呢」
   —— 没有这一格，只能退选最近的「分享」，然后被问「哪个瞬间改变了你的看法」，
   而成果展示类内容没有转折，前提不成立。
4. **工作台没有信息层级**：一屏并列三栏，没有主次。

## 三、线上实测证据（R5 全部生效）

用用户的原始例子「我画了一组水彩插画，想发出来给大家看看」走完整路径：

| 检查项 | 实测结果 |
|---|---|
| 入口 | 一个输入框 → 点「开始」→ 按钮变「正在理解…」 |
| 推断横幅 | 「我理解这是「分享」内容 — 你是想把画好的水彩插画拿出来给大家看，属于展示作品」+ 弱化的「不对，我自己选」 |
| **不再重复确认意图** | `页面上有无"确认这是一条…"：false` ✓ |
| **不再问转折** | `有无"哪个瞬间改变了你的看法"：false` ✓ |
| **问的是针对这条材料的问题** | 动作卡标题 =「这组插画是围绕什么主题或哪几幅画的？」（**不是**按意图固定的那三句之一） |
| **不再问抽象读者变化** | 可见表单字段只有"你的回答"与草稿框；`asksReaderChangeField: false` ✓ |
| 标题 | 由原料自动提炼，用户不需要先起名 |
| 版面 | 细条「进度 · 0/5 步 展开」+「参考与提醒」；行动卡是唯一焦点 |

## 四、参考项目里"值得抄的逻辑"（已读协议并落地其核心）

从 `cheat-on-content` 的 `shared-references/` 提炼出的三条可迁移纪律：

1. **样本数是信号强度的代理指标，不是信号本身**（"3 个清晰可追溯的样本 > 10 个零碎低置信度的"），
   并给出按校准池规模分级的授权表（N=1 只记录 / 2-4 候选规律 / 5-9 定性变更 / 10-19 权重微调 / **N≥20 才回归**）。
   → **已落地**为 R4 的 stage 与门槛（`creator_state`）。
2. **"见过数据"有精确边界**：只有**发布后才能获得**的信息才算数据（历史同类、同期他人不破坏盲评）。
   → TopicAI 已有盲评（先猜再看数据），边界定义可作为后续该模块的验收参考。
3. **不可篡改与软违反留痕**：预测段由 hook 强制 immutable；低于默认门槛的升格必须标注理由且**不许连环软违反**。
   → R4 的实现**不存在**低于门槛的升格路径（只有累加证据），因此"软违反"在本设计里不成立——这是比留痕更强的约束。

## 五、对照计划仍未完成的部分（如实列出）

1. **对标账号导入**（计划里的改造 5）。参考项目把它当作冷启动的关键 anchor：
   用户说不出自己是谁，但能指出"我想做成这样"。TopicAI 尚无此入口与数据模型——
   需要新表/新列 + 抓取或手工录入 + 从对标里推断选题范围与结构习惯。
2. **意图/素材/信号改为可配置 rubric 层**（参考项目的核心主张是"rubric 是循环的内容，
   不是循环本身"）。当前 `INTENT_CONFIG` 仍把三意图与其问题/素材/信号写死在代码里——
   这也是"三个选项太少"的结构性根因；R2 只是让**问题**可由推断覆盖，枚举本身仍固定。
3. 参考项目的 `MAX_DEEP_DIVE_TURNS=4` 类"反盘问上限"——TopicAI 目前没有多轮追问，
   因此暂无需要；等待"对标/画像"引入后的多轮澄清场景时再补。

## 六、本轮新增/修改的验收基准

- 端到端：展示作品类内容**不得**收到"转折瞬间"类问题（已作为线上用例）
- 入口到出第一版：**只问一个问题**且该问题来自当前材料（实测通过）
- 同一信息（读者变化 / 受众 / 目标）在产品内**只出现一次**（实测：可见字段仅"你的回答"）
- 单样本观察**不得**作为生成参考（`insight_context` 为空 + `pending_observations` 呈现 1/2）
