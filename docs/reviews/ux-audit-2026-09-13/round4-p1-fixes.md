## 二、本轮新发现的生产缺陷（PR#73）

**现象**：重部署后访问 `/login` 出现 ErrorBoundary 白屏（"页面出错了"），点"重新加载"即恢复，本地 dev 环境不复现。

**根因**：`nginx.conf` 未给 index.html 设缓存头，浏览器保留旧 index.html；新构建删除了它引用的 content-hash chunk，懒加载路由的动态导入失败 → 应用崩溃。

**影响**：每次重部署都会打中正在使用的用户——对狗粮测试者是致命的（"产品坏了"）。

**修复**：`location = /index.html { add_header Cache-Control "no-cache, no-store, must-revalidate"; expires -1; }`；hashed 资源保持 immutable 一年缓存。

**排查方法记录**：本地 dev 不复现 → 判定为构建产物特有 → 向部署页注入 `window.addEventListener('error')` 写入 sessionStorage 抓错误 → 刷新后恢复且无错误捕获 → 定位为"旧文档 + 新资源"的失配，而非代码回归。

## 三、流程失误与纠正（如实记录）

1. **两次误提交到本地 main**：#69/#71 合并后 `gh pr merge --delete-branch` 会把工作区切回 main，我沿用旧假设继续提交，导致 #70、#72 的改动落在本地 main。**恢复方式**：`git checkout -b <feature>` 保留提交 + `git branch -f main origin/main` 重置，再推 PR。**纠正**：提交前在同一命令内用 `git branch --show-current` 断言分支。
2. **两次在 CI 失败状态下合并**：轮询循环末尾的 `echo TIMEOUT` 返回成功，`&& gh pr merge` 因此照常执行。**纠正**：轮询后先读取状态字符串判断，绝不把 merge 挂在轮询循环之后。
