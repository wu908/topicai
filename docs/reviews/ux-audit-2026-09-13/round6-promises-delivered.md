## 二、文案与行为现在一致

- 收件箱/产出架：~~它会在夜里安静消化~~ → 「点『消化生产』，几十秒后变成待发布的产出；在『我的』打开夜间整理后，它也会自己动手。」（两种状态下都成立）
- 「回到灵感池」有池子可看、可回架、可删除
- 「几十秒后变成产出」是真 AI 生成（实测单条 2–15 秒）

## 三、线上核对抓到的两个真实缺陷（单测抓不到）

**#85 提示词不足以让模型产出合规 JSON**
现象：线上消化耗时 15 秒（模型确实被调用），但落库仍是确定性骨架——每次尝试都以
`LLMStructuredOutputException: Expecting ',' delimiter` 失败，降级把问题静默吞掉。
修复：system prompt 加入精确的 JSON 形状与完整示例 + `temperature=0.3`。
验证：本地用真实模型探针确认（返回真实标题/正文/大纲），再部署复验。

**#86 落库绑定的是降级常量而不是模型产出的大纲**
现象：一条 `draft_source=ai` 的产出，标题/正文/判断都来自模型，大纲却是常量。
根因：`_produce` 把草稿大纲赋给了局部变量，INSERT 仍绑定旧的 `OUTLINE`。
**为什么单测没抓住**：原断言只检查 `outline[0].step == 'hook'`，而降级常量的首步也是 hook。
修复后断言改为比对 label 并要求它不等于常量；**把修复回退该测试即失败**，回归被真正覆盖。

**方法论教训（重要）**：桩 LLM 的单测只能验证管线接线，验证不了①提示词与真实模型的合规性
②字段是否真的按预期落库。本轮两个缺陷都是"单测全绿但线上不对"，靠**真实调用 + 直接读库**才抓到。
